程序能跑了，接下来读懂它

你已经做出了任务清单。现在，我们沿着一条任务走一遍，看看代码为什么要这样写。

这一章对应你项目中的 Todo、TaskDao 和 Dbutil。每段代码都会说明它放在哪里、接收什么、做什么。你可以同时打开自己的项目，对照阅读。

这一轮先读懂已有程序。下面的代码是从项目中取出的片段，除明确标出的完整示例外，不需要单独运行。

1. 先看三个文件各管什么

选择“添加任务”后，程序要接收文字、连接数据库、执行 SQL。把这些事情放到不同的类中，查问题时就容易找到对应的位置。

文件负责的事情
Todo.java显示菜单，接收输入，调用相应功能。
TaskDao.java组织任务相关的 SQL，执行添加、查询、修改和删除。
Dbutil.java保存连接配置，提供连接数据库的方法。

DAO 是一种常见命名，意思是负责数据访问的对象。在你的项目里，TaskDao 就是“替任务清单读写数据库的类”。这个名字来自开发习惯，Java 不要求类必须叫它。

Todo 接收输入 → TaskDao 执行操作 → Dbutil 提供连接 → MySQL 保存数据

TaskDao 执行 SQL 时会调用 Dbutil 获取连接。上图表示合作关系，真正的执行顺序在后面逐行展开。

2. 变量、对象和方法，怎么连起来？

TaskDao dao = new TaskDao();
dao.insert(content, date);

第一行创建一个 TaskDao 对象，并用变量 dao 保存它的引用。你可以把引用理解成找到这个对象的方式。第二行通过 dao，调用这个对象的 insert 方法，把 content 和 date 交给它。

写法含义
TaskDao变量所使用的类型。
dao你给变量起的名字，可以换名，但后面的使用要一致。
new TaskDao()创建对象。这里会调用 TaskDao 的无参数构造方法。
dao.insert(...)在这个对象上执行 insert 方法。

你的 TaskDao 没有写构造方法，Java 会提供默认的无参数构造方法。再看被调用的方法：

public void insert(String content, String taskDate) {
    // 添加任务的代码放在这里
}

public 允许其他类调用它。void 表示执行完不返回一个值。insert 是方法名。括号里声明两个字符串参数，方法通过它们接收调用者交过来的文字。

调用 dao.insert(content, date) 时，第一个值交给方法里的 content，第二个值交给 taskDate。参数按位置对应，调用前后的变量名不必相同。

再看 Dbutil.getConnection()：它通过类名直接调用，因为 getConnection 声明成了 static。static 方法属于类，可以直接调用；insert 没有 static，我们通过创建的 dao 对象调用它。

3. import 和 Maven，各做什么？

假设你想读终端输入，需要使用 Java 提供的 Scanner。它的完整名称是 java.util.Scanner。文件开头写：

import java.util.Scanner;

写完后，下面可以直接用 Scanner 这个短名称。import 让编译器知道你说的是哪个类。它本身不下载文件，也不创建对象。

Scanner sc = new Scanner(System.in);

这一行才创建读取输入的对象。System.in 表示标准输入，在当前程序中就是终端输入。

工具来源用途
Scanner、List、ArrayListJava 自带，位于 java.util 包。读取输入，保存列表。
Connection、PreparedStatement、ResultSetJava 自带，位于 java.sql 包。描述连接、SQL 操作和查询结果。
Gson外部库，由 Maven 下载。转换 Java 数据与 JSON。
MySQL Connector/J外部库，由 Maven 下载。实际完成 JDBC 与 MySQL 之间的通信。

java.sql 提供了数据库操作的接口；MySQL 驱动提供与 MySQL 通信的具体实现。所以，代码能识别 Connection，并不代表已经有了 MySQL 驱动。

pom.xml 为什么需要依赖信息？

<dependency>
    <groupId>com.mysql</groupId>
    <artifactId>mysql-connector-j</artifactId>
    <version>9.5.0</version>
</dependency>

这段放在项目根目录 pom.xml 的 dependencies 中。它指定“哪一组提供者、哪个库、哪个版本”。Maven 按这个信息下载库，并把库加入项目的编译和运行环境。

新依赖的坐标通常从库的官方文档查找。包名可以查类的文档，或让编辑器根据类名补充 import。你需要理解它的用途，无须背下所有包名。

你的 import java.sql.*; 表示允许使用 java.sql 包中的类型短名称。它不包含子包，也不等于安装 MySQL。TaskDao 与 Dbutil 当前没有 package 声明，位于同一个默认包中，因此它们之间可以直接按类名引用。

程序怎么运行时带上依赖？

先在含 pom.xml 的项目目录执行 mvn compile。运行 Todo 可以点击 VS Code 中 main 上方的 Run，或在同一目录执行：

mvn compile exec:java -Dexec.mainClass=Todo

Maven 会为运行准备项目所需的依赖。后面切换电脑时，依赖清单仍保存在 pom.xml 中，Maven 可以重新下载。

4. 跟着“添加任务”走一遍

先看 Todo 中接收内容的部分：

String content = sc.nextLine();
dao.insert(content, date);

假设用户输入“学习集合”，日期字符串是“11月11日星期三”。调用 insert 后，方法中的 content 和 taskDate 就分别拿到这两个值。

接着进入 TaskDao：

String sql = "insert into tasks (content, task_date) values (?, ?)";
try (Connection conn = Dbutil.getConnection();
     PreparedStatement ps = conn.prepareStatement(sql)) {
    ps.setString(1, content);
    ps.setString(2, taskDate);
    ps.executeUpdate();
} catch (SQLException e) {
    e.printStackTrace();
}

第一行创建一段 SQL 文字，它还没有发送出去。两个问号留出要填写的位置。接下来，Dbutil.getConnection() 使用连接地址、用户名和密码连接 MySQL，并返回 Connection。

conn.prepareStatement(sql) 通过这条连接准备 SQL 操作。随后，setString(1, content) 填第一个位置，setString(2, taskDate) 填第二个位置。这里的编号从 1 开始。

最后，executeUpdate() 才执行添加操作。PreparedStatement 把输入作为参数值处理，因此任务中出现引号时也不需要自己拼接 SQL。

executeUpdate() 返回受影响的行数。你当前没有接收这个值。以后想提示“添加成功”，可以用一个 int 变量接收，再根据结果输出。

Dbutil 在哪里参与？

public static Connection getConnection() throws SQLException {
    return DriverManager.getConnection(URL, USER, PASSWORD);
}

这个方法向驱动管理器请求连接，再通过 return 把连接交给调用它的 TaskDao。返回类型 Connection 告诉我们它会交回什么。throws SQLException 表示连接失败时，异常可以交给调用它的代码处理；上面的 catch 就负责接住这个异常。

如果看到 Class.forName("com.mysql.cj.jdbc.Driver")，那是在按完整类名请求加载驱动。现代 JDBC 驱动通常可以自动发现；你当前显式加载时，必须把类名写准确，否则连接代码还没执行就会失败。

5. 数据库里的结果，怎么回到菜单？

List<String> tasks = dao.findALl();
for (String t : tasks) {
    print(t);
}

这段位于 Todo。findALl() 返回一个字符串列表，Todo 用 tasks 接收，然后逐行打印。你的方法名中 ALl 的大小写就是当前代码的写法，调用时必须保持一致。

再进入 TaskDao.findALl：

List<String> result = new ArrayList<>();
String sql = "select id, content, task_date from tasks order by id";
try (Connection conn = Dbutil.getConnection();
     PreparedStatement ps = conn.prepareStatement(sql);
     ResultSet rs = ps.executeQuery()) {
    while (rs.next()) {
        result.add(rs.getInt("id") + " | "
                + rs.getString("content") + " | "
                + rs.getString("task_date"));
    }
} catch (SQLException e) {
    e.printStackTrace();
}
return result;

List<String> 表示列表里装字符串，ArrayList 是这里使用的具体列表实现。new ArrayList<>() 创建一个空列表；右边的尖括号让编译器根据左边推断元素类型。

executeQuery() 执行查询，返回 ResultSet。可以把它理解成一批还需要逐行读取的结果。rs.next() 移到下一行：有下一行时返回 true，循环继续；没有下一行时返回 false，循环结束。

每轮循环按列名取值，把编号、内容和日期拼成一行，再用 result.add(...) 放进列表。return result 把这个列表交回 Todo。到了这里，一次查询才走完：

MySQL 的行 → ResultSet 逐行读取 → List<String> → Todo 打印

“看今天任务”多做了什么？

findTodayTask(date) 在 SELECT 中增加 WHERE task_date = ?，然后通过 ps.setString(1, date) 填入日期。数据库只返回日期文字完全相同的行。当前日期是展示用的文字，若要按先后排序或跨年查询，后续应改成统一的完整日期并使用 DATE 列。

修改和删除也是相同的过程

updateTask 先准备 UPDATE，再填入新内容和编号；deleteById 准备 DELETE，再填入编号。它们用 executeUpdate() 执行。WHERE 决定处理哪一行，省略它会影响整张表。

6. try、catch 和括号，为什么这样放？

数据库连接使用完后需要关闭。否则程序长期运行时，会占着越来越多的连接。Java 的 try-with-resources 可以在代码离开这一段时自动关闭资源：

try (Connection conn = Dbutil.getConnection();
     PreparedStatement ps = conn.prepareStatement(sql)) {
    // 使用 conn 和 ps
} catch (SQLException e) {
    e.printStackTrace();
}

try 后面的圆括号声明需要自动关闭的资源，用分号隔开。花括号里面放操作。执行结束或发生异常时，Java 会关闭已经成功创建的资源，关闭顺序与创建顺序相反。

catch 接住 SQLException，e 保存异常信息。printStackTrace() 输出调用路径，方便定位出错的位置。它不会自动重试，也不会把失败变成成功。

你的查询方法在失败时打印异常，然后仍返回 result。如果此时 result 为空，菜单就可能只显示一个空列表。以后需要向用户区分“没有任务”和“查询失败”，可以让异常继续向上传递，或设计明确的结果返回方式。

7. 菜单怎么重复，输入为什么要处理换行？

while (true) 让菜单重复执行。switch 根据选项选择分支，case 2 -> 对应添加任务。退出分支的 return 结束 main，程序随之结束。

int choice = sc.nextInt();
sc.nextLine();
String content = sc.nextLine();

这三行演示连续读取的过程。用户输入数字并按回车后，nextInt() 取走数字，换行还留在输入里。第一条 nextLine() 读掉当前行剩余的内容；第二条 nextLine() 才等待任务文字。在你的代码中，第二条位于添加任务分支。

如果输入字母，nextInt() 会抛出 InputMismatchException。后面改进输入时，可以改成先读取整行文字，再尝试用 Integer.parseInt 转成数字，并在转换失败时提示重新输入。

你已经给清屏写了 clearScreen()。调用位置决定何时清屏：放在 main 开头，只清一次；放在循环开头，每轮都清。若每轮清屏，要在显示结果后等待用户按回车，否则刚打印的任务会马上消失。

8. 从 JSON 到 MySQL，什么发生了变化？

JSON 版本MySQL 版本
Gson 把文件转成任务列表。SELECT 查询任务，ResultSet 接收结果。
在列表中加入任务，再写回整个文件。INSERT 添加一行。
遍历列表查找并删除。DELETE 按编号删除。
代码自己计算新编号。AUTO_INCREMENT 生成编号。

两种版本都在完成相同的需求：接收任务、保存任务、取出任务。保存的位置和操作方式发生了变化，菜单仍然可以保持原来的使用方式。

你在这一过程中实际用到了类和方法、字符串、集合、循环、异常、外部依赖与数据库。它们现在都能对应到项目中的一段代码。

9. 下次遇到看不懂的代码，怎么读？

先找到你想理解的功能入口，例如添加任务的 case 2。读到方法调用时，跳到方法定义，确认参数是什么、结果是什么。遇到新类，先判断来源，再查它的方法用途。

  1. 圈出输入。例如任务内容和日期。
  2. 找到处理这些输入的方法，例如 insert。
  3. 找出真正产生效果的语句，例如 executeUpdate。
  4. 查看返回值和异常会交给谁。

你可以先用自己的话说明一次添加任务：Todo 得到文字，TaskDao 准备 SQL，Dbutil 提供连接，驱动把命令交给 MySQL。能解释这一条路径后，再读查询路径。
