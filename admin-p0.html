第一步：给前端的回复，先装进一个盒子

你的登录接口已经能收到账号密码，并把处理结果返回。我们接下来整理返回格式。

前端可能收到登录结果、用户列表或错误提示。每次都让它找相同的三个字段，代码就容易写：code 表示结果，msg 放提示，data 放具体内容。

Postman → LoginHandler 接收请求 → AuthService 检查 → Repository 查数据库
Postman ← LoginHandler 用 Result 装好回复 ← 检查结果

可以把 Result 想成一个外卖盒：盒上的标签总有状态和说明；盒子里可以装不同的内容。现在我们先做一个成功的盒子。

先看你写好的盒子

在 Result.java 中，Result<T> 的 T 给数据类型留位置。Result<String> 表示 data 装文字；Result<SysUser> 表示 data 装用户对象。

再加一个装成功结果的方法

在 Result 类里、三个字段后面加入这段方法：

public static <T> Result<T> success(T data) {
    // 先创建一个空盒子。
    Result<T> result = new Result<>();
    // 写上成功代码和提示。
    result.code = 200;
    result.msg = "成功";
    // 把收到的数据放进盒子。
    result.data = data;
    return result;
}

public 允许其他类调用；static 表示可以通过 Result.success(...) 调用，不必先在外面创建盒子。方法名前的 <T> 让这个静态方法自己声明数据类型；Result<T> 是返回类型，T data 是接收的数据，return 把装好的盒子交回调用者。

例如调用 Result.success("登录成功")，得到的 data 是文字。后续接口返回给前端时，会看到 code、msg、data 三个字段。我们下一步再把 LoginHandler 接上它。

阅读进度：这一段只是在 Result 中新增方法。登录接口暂时不会自动改变；需要后续显式调用它。登录响应应选择安全字段，不能把密码哈希返回给前端。

下一步：登录接口用上结果盒子

登录流程仍然从 Postman 进入 LoginHandler，AuthService 查询并验证用户。验证通过后，LoginHandler 把安全字段放进 data，再用 Result.success 打包回复。

Postman → LoginHandler → AuthService → Repository → MySQL
Postman ← Result<安全字段> ← LoginHandler ← 用户信息

餐厅做好菜以后，打包员只把客人需要的菜放进外卖盒。这里也先挑选用户编号和用户名，再放进结果盒子；数据库对象中的密码哈希留在服务端。

在 LoginHandler.java 的 import 区域加入：

import com.first.common.Result;

将已有的 login 方法替换为下面的方法。Map、HashMap、SysUser、PostMapping 和 RequestBody 沿用文件中已有的 import；不要在同一个类中保留两个相同的 /login 方法。

@PostMapping("/login")
public Result<Map<String, Object>> login(
        @RequestBody Map<String, String> loginData) {
    // 从请求正文取账号和密码。
    String username = loginData.get("username");
    String password = loginData.get("password");

    // 交给业务层校验；通过后得到用户对象。
    SysUser user = authService.login(username, password);

    // 只挑选前端需要的信息。
    Map<String, Object> data = new HashMap<>();
    data.put("id", user.getId());
    data.put("username", user.getUsername());

    // 使用刚写好的方法，生成统一的成功回复。
    return Result.success(data);
}

PostMapping 保留 POST /api/auth/login 的路径；RequestBody 让 Spring 从 JSON 正文读取键值；Map<String, String> 里是字符串键和值。Result<Map<String, Object>> 说明回复盒子的 data 是一个 Map，其值可以包含不同类型，例如数字编号与字符串用户名。

重启程序，用已有的 Postman 登录请求测试。正确账号和密码应得到含 code、msg、data 的 JSON，data 中只有 id 和 username。此阶段错误仍由现有代码抛出，统一错误处理留到后面。
