09 / 任务清单实战

把任务从 JSON 搬到 MySQL

你的任务清单已经能把任务存进 JSON 文件了。现在，我们来试试把它们放进数据库。

先想一想你现在的程序：添加一条任务时，要先读出整个列表，加入新任务，再把整个列表写回文件。如果任务越来越多，你想按编号找一条、按日期找今天的任务，每次都要自己处理整个列表。

MySQL 可以帮你保存一张任务表；你告诉它“加一条”或“找今天的”，它负责处理数据。这一章我们会先亲手用 MySQL 增删查，再让 Java 替我们发出同样的命令。

这章怎么学？ 我们沿用你已经做好的任务清单。先在旁边建一个独立的连接练习，确认能写入和读取，再把思路接回原程序。原来的 JSON 文件先留着。

先看全程

启动 MySQL → 建任务表 → Java 连接 → 添加与查询 → 接回清单

读完这一章，你会知道数据库、表、SQL、Maven 依赖和 JDBC 分别在做什么，也能在 Java 中真正保存一条任务。

先回头看：你现在的程序做了什么

在开始之前，我们用你的代码把已经学过的东西串起来。

你把任务放在 List<Task> 里。保存时，save_tasks() 让 Gson 把列表变成 JSON，再写入 data/task.json；下次启动，load_tasks() 读出 JSON，再交给 Gson 变回任务列表。

任务列表 → Gson 转换 → JSON 文件
JSON 文件 → Gson 转换 → 任务列表

Gson 是别人写好的工具。pom.xml 记录项目需要它，Maven 负责下载它并在编译和运行时提供给项目。MySQL 的连接工具也按同样的方式加入；你不用重新写一份 pom.xml。

接下来我们不会一边往 JSON 写一边往 MySQL 写。先独立验证数据库，再考虑如何切换保存方式，避免两份数据让人混淆。

09 / 任务清单实战

第一站：把 MySQL 启动起来

MySQL 本身是一个提供数据服务的程序。它需要先运行起来，Java 才能连接它。我们用你学过的 Docker 启动。

1.1 先检查有没有现成容器

打开 Docker Desktop，等它启动完成。然后在终端输入：

docker ps -a  # 查看所有容器，包括已经停止的

看 NAMES 一列。如果已经有 study-mysql，先用下面的命令启动已有容器：

docker start study-mysql
docker logs study-mysql

如果它已经在运行，直接查看日志即可。请使用创建这个容器时设置的密码；重新运行创建命令不会替你改掉已有容器的密码。

1.2 没有容器时，再创建一个

如果列表里没有 study-mysql，运行：

docker run -d --name study-mysql \
  -e MYSQL_ROOT_PASSWORD=study_password \
  -p 127.0.0.1:3306:3306 \
  -v study-mysql-data:/var/lib/mysql \
  mysql:8.0

这条命令让 Docker 启动 MySQL 8.0。study_password 是本机练习用的密码；3306:3306 让本机可以通过 3306 端口连接容器；-v 给数据库使用一个具名数据卷，用来保留数据。

第一次下载镜像和初始化可能要等一会儿。用 docker logs study-mysql 看日志，等出现类似 ready for connections 的信息，再继续。如果本机 3306 被占用，创建新容器时可改用 -p 127.0.0.1:3307:3306；后面的 JDBC 地址也要相应改成 3307。

一个容易弄混的地方：停止容器和删除容器是两回事。这里的数据卷与容器分开保存；不要删除数据卷，除非已经确定不再需要里面的数据。

1.3 进入 MySQL

docker exec -it study-mysql mysql -u root -p

看到 Enter password: 时输入密码并按回车。屏幕不会显示输入的字符，这是正常的。如果是按上面的命令新创建的容器，密码就是 study_password。进入后看到 mysql>，说明你正在和 MySQL 说话。

如果日志已经显示就绪却仍连接失败，先看本章末尾的排查表。

09 / 任务清单实战

第二站：亲手创建任务表

现在我们先不用 Java，直接在 MySQL 里建好存放任务的地方。

2.1 数据库、表和一行数据是什么？

可以把数据库想成一个文件夹，表想成文件夹里的一张表格。我们创建一个叫 todo_app 的数据库，里面放一张叫 tasks 的表；每一行代表一条任务。

idcontenttask_date
1学习 Java2026-11-09
2整理笔记2026-11-09

在 mysql> 后输入下面的命令。每条命令以分号结束，输入后按回车：

CREATE DATABASE IF NOT EXISTS todo_app
  CHARACTER SET utf8mb4;
USE todo_app;

第一条创建数据库；IF NOT EXISTS 表示不存在时才创建。utf8mb4 让它能够保存中文等文字。第二条选择接下来要使用的数据库。

2.2 创建表

CREATE TABLE IF NOT EXISTS tasks (
    id INT PRIMARY KEY AUTO_INCREMENT,
    content VARCHAR(255) NOT NULL,
    task_date VARCHAR(40) NOT NULL
);

逐行看：id 是整数编号，PRIMARY KEY 要求每行编号唯一，AUTO_INCREMENT 让数据库为新任务生成编号；content 保存任务文字；task_date 保存日期文字；NOT NULL 表示这一列不能为空。

这里先用文字保存日期，是为了和你目前的 Task.date 类型接得上。后面学习日期查询时，可以再改成数据库的 DATE 类型。

2.3 自己增、查、删一次

INSERT INTO tasks (content, task_date)
VALUES ('练习 MySQL', '2026-11-09');

SELECT id, content, task_date FROM tasks;

INSERT 是添加一行；我们没有填写 id，因为 MySQL 会自动生成。SELECT 是查询，你应该看到“练习 MySQL”和它的编号。MySQL 中的一行对应你原来列表中的一个任务对象。

如果刚才的练习任务编号是 1，可以这样删除它；如果你的编号不是 1，请换成实际看到的编号：

DELETE FROM tasks WHERE id = 1;
SELECT id, content, task_date FROM tasks;

WHERE id = 1 的意思是只处理编号为 1 的那一行。不要省略 WHERE：没有筛选条件的删除会删除表里的所有行。

这一章沿用你现在的规则：完成任务时删除它。如果以后想保留完成历史，可以增加“是否完成”这一列，把删除改成更新状态。

第三站：让 Java 找到 MySQL

你已经能在 MySQL 里输入 SQL 了。接下来，让 Java 替你发送这些命令。

3.1 JDBC 和驱动分别是什么？

JDBC 是 Java 提供的一套数据库操作方式：代码可以用它连接数据库、发送 SQL 和读取结果。具体怎么和 MySQL 沟通，则需要 MySQL 提供的驱动，名字叫 Connector/J。

你的 Java 代码 → JDBC → MySQL 驱动 → MySQL 服务

类比一下你已经用过的 Gson：Java 程序需要一个外部工具，就把它写进 pom.xml，交给 Maven 下载。

3.2 在已有的 pom.xml 增加依赖

打开项目根目录的 pom.xml。找到已有 Gson 的 <dependencies>，在 Gson 的 </dependency> 后面、</dependencies> 前面，增加下面这一段：

<!-- 让 Java 可以连接 MySQL -->
<dependency>
    <groupId>com.mysql</groupId>
    <artifactId>mysql-connector-j</artifactId>
    <version>9.5.0</version>
</dependency>

加完以后，同一个 <dependencies> 里会有两段 <dependency>：一段是已有的 Gson，另一段是 MySQL 驱动。前者继续供 JSON 代码使用，后者用于连接数据库。

保存后，在包含 pom.xml 的项目目录运行：

mvn compile

第一次 Maven 会下载依赖；看到 BUILD SUCCESS，说明项目编译通过。如果 VS Code 仍有红线，先确认打开的是包含 pom.xml 的整个项目文件夹，再等待 Java 项目导入完成。MySQL 驱动坐标可在 MySQL 官方文档查到。

第四站：先试着连上数据库

这一步只检查“能不能连接”，不修改你已经写好的任务清单。

4.1 建一个单独的连接练习

在现有项目的 src/main/java 里，新建文件 DatabaseDemo.java。把下面的代码写进去：

import java.sql.Connection;
import java.sql.DriverManager;
import java.sql.SQLException;

public class DatabaseDemo {
    public static void main(String[] args) {
        String url = "jdbc:mysql://127.0.0.1:3306/todo_app";
        String user = "root";
        String password = "study_password";

        try (Connection connection = DriverManager.getConnection(url, user, password)) {
            System.out.println("连接成功！数据库：" + connection.getCatalog());
        } catch (SQLException e) {
            System.out.println("连接失败：" + e.getMessage());
        }
    }
}

这几行分别是什么意思？

代码作用
jdbc:mysql://表示通过 JDBC 连接 MySQL。
127.0.0.1:3306连接你自己的电脑上 3306 端口的 MySQL。
todo_app要进入的数据库名称。
getConnection(...)用地址、用户名和密码建立连接。
try (...)代码执行完后自动关闭连接。

如果你之前创建容器时用的是其他密码，修改 password；如果本机端口改成了 3307，地址也改成 127.0.0.1:3307。示例里的密码仅用于本机练习，不要把真实密码提交到 GitHub。

4.2 运行连接练习

推荐在 VS Code 中打开整个 Maven 项目，等待项目加载完成，然后打开 DatabaseDemo.java，点击 main 方法上方的 Run。

也可以在项目根目录用 Maven 运行：

mvn compile exec:java -Dexec.mainClass=DatabaseDemo

正常情况下会看到 连接成功！数据库：todo_app。注意：即使你还开着 mysql>，输入这条 Maven 命令也要回到普通终端；可以输入 exit 退出 MySQL 客户端，或者打开新的终端标签。退出客户端不会停止 MySQL 容器。

如果连接失败：先不要改一大堆配置。看错误文字，再对照文末的排查表：服务是否启动、端口、密码、数据库名称是否一致。
09 / 任务清单实战

第五站：用 Java 添加和查看任务

连接成功以后，我们让 Java 做刚才在 MySQL 里手动做过的事：执行 INSERT 和 SELECT。

为了先把过程看清楚，我们继续用独立练习文件。将 DatabaseDemo.java 的内容替换为下面的完整示例。它只向 todo_app.tasks 添加一条练习任务并打印列表；每运行一次都会再新增一条。

import java.sql.Connection;
import java.sql.DriverManager;
import java.sql.PreparedStatement;
import java.sql.ResultSet;
import java.sql.SQLException;

public class DatabaseDemo {
    public static void main(String[] args) {
        String url = "jdbc:mysql://127.0.0.1:3306/todo_app";
        String user = "root";
        String password = "study_password";

        String insertSql = "INSERT INTO tasks (content, task_date) VALUES (?, ?)";
        String selectSql = "SELECT id, content, task_date FROM tasks ORDER BY id";

        try (Connection connection = DriverManager.getConnection(url, user, password)) {
            // 插入一条任务
            try (PreparedStatement insert = connection.prepareStatement(insertSql)) {
                insert.setString(1, "练习 JDBC");
                insert.setString(2, "2026-11-09");
                int count = insert.executeUpdate();
                System.out.println("添加了 " + count + " 条任务");
            }

            // 读取并打印任务
            try (PreparedStatement query = connection.prepareStatement(selectSql);
                 ResultSet results = query.executeQuery()) {
                while (results.next()) {
                    int id = results.getInt("id");
                    String content = results.getString("content");
                    String date = results.getString("task_date");
                    System.out.println(id + " | " + content + " | " + date);
                }
            }
        } catch (SQLException e) {
            System.out.println("数据库操作失败：" + e.getMessage());
        }
    }
}

保存后，用 VS Code 的 Run，或者再次在项目根目录运行：

mvn compile exec:java -Dexec.mainClass=DatabaseDemo

如果看到“添加了 1 条任务”和任务列表，说明 Java 已经能写入并读取 MySQL。你也可以回到 MySQL 客户端，执行 USE todo_app; 和 SELECT * FROM tasks;，看看它们是不是同一批数据。

5.1 那两个问号是什么？

VALUES (?, ?) 是两个待填写的位置。insert.setString(1, ...) 填第一个位置，setString(2, ...) 填第二个。PreparedStatement 会把参数作为值处理；用它比把用户输入直接拼到 SQL 中更合适，也能避免常见的 SQL 注入问题。

5.2 为什么要 results.next()？

查询可能返回多行。ResultSet 代表这批结果，next() 把位置移到下一行：有下一行就返回 true，没有就结束循环。在每一行里，通过列名读取 id、content 和 task_date。

5.3 完成任务时怎么删除？

你的原程序把“完成”实现成删除。数据库里也可以按编号删除，SQL 写法是：

String sql = "DELETE FROM tasks WHERE id = ?";
try (PreparedStatement delete = connection.prepareStatement(sql)) {
    delete.setInt(1, id);  // id 是用户输入的整数
    int count = delete.executeUpdate();
    System.out.println(count == 0 ? "没有找到这条任务" : "任务已完成");
}

这是一段方法内部的片段：需要已有的 connection 和整数 id。executeUpdate() 返回受影响的行数；为 0 表示没有匹配的任务。记得保留 WHERE id = ?。

09 / 任务清单实战

第六站：接回你的任务清单

现在，数据库已经能独立工作。接回原程序时，我们一项一项替换，避免改完一大堆才不知道哪里出了问题。

6.1 先对照旧代码

现在的 JSON 版本改成 MySQL 后
load_tasks：读完整个文件执行 SELECT，需要什么任务就查询什么
addTask + save_tasks：加入列表并写回文件执行 INSERT，由数据库保存新任务
get_next_id：遍历列表找最大编号插入时不提供 id，由 AUTO_INCREMENT 生成
finish_task：从列表删除再写文件执行带 WHERE 的 DELETE

最实用的做法是新建一个类，例如 TaskRepository，让它专门负责与数据库交谈：添加、查询、按编号删除。菜单仍然负责询问用户要做什么，不必知道 SQL 的每个细节。

6.2 按这个顺序接

  1. 先接查询：把“查询并打印”的代码整理成一个方法，让菜单“查看全部任务”调用它。运行并确认能看到数据库里的任务。
  2. 再接添加：把用户输入的内容和日期传给 INSERT，添加后重新查询确认。数据库会分配 id，所以不需要先调用 get_next_id()。
  3. 最后接完成：把输入的编号交给 DELETE，根据返回的行数提示是否找到任务。
  4. 重启检查：关闭并重启 Java 程序，确认任务仍在；再停止和启动容器，确认数据卷中的任务仍在。
关于已有 JSON：新数据库刚建好时是空的，原来 data/task.json 中的任务不会自动进入数据库。先保留文件；等新增、查询和删除都跑通后，再单独设计一次导入，不要边试验边覆盖旧数据。

6.3 这一阶段做到什么程度？

完成后，你应该能在自己的菜单中添加任务、查看任务、输入编号完成任务；关闭程序再打开，尚未完成的任务仍然在。JSON 文件可以留作旧数据备份。

碰到问题时，先检查哪里？

连接数据库涉及几处不同的地方。看报错时，先找出它是在说哪个环节。

现象可以先做什么
Docker 连不上 daemon打开 Docker Desktop，等它完全启动后再运行 docker ps。
容器名已经存在用 docker ps -a 检查，已有容器用 docker start study-mysql 启动。
端口被占用用 lsof -i :3306 查看。创建新容器时可改本机端口，JDBC 地址也要同步修改。
Access denied检查用户名、密码；已有容器使用的是之前初始化时的密码。
Communications link failure / Connection refused检查容器是否运行、MySQL 是否已初始化完成、主机和端口是否正确。
Unknown database 'todo_app'回到 MySQL 客户端执行创建数据库的步骤，确认名称一致。
Table 'todo_app.tasks' doesn't exist确认执行过 USE todo_app 和建表语句。
No suitable driver检查 pom.xml 是否添加 Connector/J，项目是否按 Maven 方式运行；URL 是否以 jdbc:mysql: 开头。

如果错误信息不在表里，先保留完整报错，再从第一行关键提示查起。你可以把正在执行的命令和报错一起带回来，我们接着排查。
