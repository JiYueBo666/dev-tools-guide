功能多了，代码怎样安放？

你已经把数据库操作放到 TaskDao。框架项目继续沿用这种分工，只把职责讲得更明确。

任务清单里同时有三类事情：HTTP 地址和状态码，任务该遵守的规则，以及数据库怎样读写。把它们全塞进一个类里，改一次规则就容易碰到无关代码。

我们可以把一次操作写成“Controller 接收请求，Service 处理业务，Repository 访问数据”。图片中的 handler 在 Java MVC 项目中常由 Controller 承担。你原来的 TaskDao 与 Repository 在职责上相近。

先看它们怎样合作

Controller 读取 CreateTask，把 content 交给 service。Service 判断是否允许创建，再调用 repository。Repository 保存并返回结果，Controller 决定 201 和 Location。业务规则因此不需要知道 HTTP 的每个细节。

第一篇先把存储留在 TaskService 内存中，让第一阶段能独立运行。进入数据库阶段，再把存储操作抽到 Repository。这里只在职责确实增加时拆分，不要求每个简单动作都堆一层空转发。

谁来创建 service？

你以前写 new TaskDao()。在你前面写的 TaskController 中，构造方法是：

private final TaskService service;
public TaskController(TaskService service) {
    this.service = service;
}

它明确表示“创建控制器，需要一个 TaskService”。Spring 发现 @Service 标记的类，准备相应对象，再把它交给控制器的构造方法。这个把需要的对象从外面传进来的方式叫依赖注入。

因此你仍能看出依赖关系：看构造方法，就知道这个类需要谁。框架负责日常装配，单元测试中也可以自己创建一个假 Repository，再 new TaskService(fakeRepository)。Spring 还有其他注入方式，这里优先使用构造方法让依赖可见。

通常这些组件是单例，多个请求会共享同一个对象。不要在字段里存“当前请求的用户”或使用普通 ArrayList 随意并发写入。前面写的 TaskService 用并发容器保存练习任务，业务持久化仍应交给数据库。

同一份代码，换台电脑怎么运行？

端口、数据库地址、上传目录和密码会随环境变化。把它们写死在 Java 文件里，每换环境就要改代码和重新打包。可以在 src/main/resources/application.yaml 中集中配置，再用环境变量覆盖：

server:
  port: ${PORT:8090}

这表示有 PORT 环境变量就使用它，没有就默认 8090。PORT=8091 mvn spring-boot:run 就会换一个端口。数据库密码也应通过环境提供，而不是提交到仓库。Spring Boot 不会自动把任意 .env 文件当配置加载，使用 .env 时还需要启动工具或显式导入安排。

日志要让人能找，也让程序能筛

System.out.println 适合最初观察。请求多了，你会想按时间、级别、请求编号查找。示例使用 SLF4J 的 Logger，消息模板里用 {} 放值：

log.info("method={} path={} status={} durationMs={}",
        method, path, status, durationMs);

INFO 记录重要的正常事件，DEBUG 记录开发排查细节，WARN 记录需要关注的异常情况，ERROR 记录失败。级别反映事件意义，不能所有请求都打 ERROR。密码、令牌和完整私有请求体也不应写进日志。

后面这份日志配置先使用便于阅读的文字格式，MDC 中的 requestId 会出现在方括号里。部署后若需要集中检索，可在 Spring Boot 4.1.2 配置 logging.structured.format.console: logstash，让输出成为结构化 JSON。它与 Go 的 slog、zap 解决相似的记录问题。跨服务追踪可在以后接入 Micrometer Tracing，并按链路传播规则携带 traceId。

参考：Spring Boot 日志。

把日志格式写到看得见的地方

将之前只有端口的 application.yaml 扩展如下。server.address 限制本机访问；PORT 允许启动时覆盖端口；logging 设置级别和显示格式；multipart 只在你接上传时限制文件大小。

server:
  address: 127.0.0.1
  port: ${PORT:8090}
logging:
  level:
    root: INFO
    com.example.todo: INFO
  pattern:
    console: "%d{HH:mm:ss} %-5level [%X{requestId}] %logger{24} - %msg%n"
spring:
  servlet:
    multipart:
      max-file-size: 2MB
      max-request-size: 3MB

日志格式中的 %X{requestId} 读取我们放进 MDC 的编号。每一项都对应前面的一项行为。重启后发一次请求，再把响应编号与终端日志对上即可。
