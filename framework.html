让 Spring Boot 接手重复的工作

你已经知道一条 HTTP 请求怎样到达 Java。接下来，我们让已有的任务清单真正提供接口。

你的 TaskDao 已经能查数据库。如果想把它放到网页后面，还要接收连接、分辨请求地址、读取 JSON、检查输入、整理响应。只做一个接口时，这些代码还不算多；添加、修改、上传和登录都接进来以后，相似的工作会反复出现。

Spring Boot 会帮你把常用组件配置好。它启动 Web 服务器，让 Spring MVC 按地址找到处理方法，把 JSON 转成 Java 数据，再把返回值转换成响应。你仍然决定任务规则、数据保存方式，以及用户可以做什么。

我们沿用任务清单，慢慢把这些分工说清楚。先有一条能访问的请求，再谈输入错误、文件上传、统一日志。等入口顺畅了，再接回数据库。这样你能看见每一层在替你做哪件事。

这部分怎样接着读

第一篇先把请求交到一个 Java 方法手里；第二篇讲用户输入怎样变成可用的数据；第三篇把日志、鉴权和跨域放进请求经过的公共通道；第四篇整理类、配置和依赖。后面三篇再接数据库、解释 ORM 容易踩的地方，并用自动测试留下检查方法。

  • 一：网页敲门，谁来接待？
  • 二：收到的内容，怎样放心使用？
  • 三：每条请求都要做的事，放在哪里？
  • 四：功能多了，代码怎样安放？

  • 六：代码变短以后，数据库还在做什么？

从一个空文件夹开始

你已经会写 Java，也用过 Maven。接下来就从这两样工具出发：自己建目录，写 pom.xml，写 main，再写第一个接收请求的方法。每增加一个文件，都说明它放在哪里、由谁使用。

第一篇先让浏览器看到一句话。到这一步只需要两个 Java 文件和一小段端口配置。后面再慢慢长出任务接口、校验、错误处理和日志。你能看见每一部分怎样进入项目。

我们使用 Spring Boot 4.1.2，编译目标 Java 21。先确认 java -version 和 mvn -version 对应的 Java 环境符合要求。框架依赖仍由 Maven 按你写下的清单获取，具体用到哪些依赖会在创建 pom.xml 时逐项解释。
