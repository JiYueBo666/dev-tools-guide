08 / JAVA 入门

Java 入门：一起做一份任务清单

假如你想写一个小程序，记下今天要做的事。任务怎么表示？多条任务放在哪里？关掉程序后，怎么留住它们？

这些问题，正好能带我们认识 Java 的常用工具。你不必一上来就记住所有名字：我们先解决一个小问题，再看看 Java 给它起了什么名字。

怎么学这章？ 标有文件名的示例是独立小程序；少量短代码用于解释写法，会标明是片段。先运行、观察结果，再自己改一点。如果某一节看累了，就先停在那一节；这些例子可以反复回来试。

这章要走的路

你会遇到的问题我们会学什么
怎么描述一条任务？类、对象、方法、权限、继承和接口
怎么存很多条任务？List、Set、Map、泛型和遍历
怎么筛选未完成的任务？Lambda、Stream 和 Optional
怎么把任务保存到文件？异常、文件读写和序列化
框架怎么认识我们的代码？反射和注解

先让 Java 跑起来

我们需要 JDK：它提供编译和运行 Java 程序所需的工具。先打开终端，检查一下：

java -version      # 查看运行 Java 程序的工具
javac -version     # 查看 Java 编译器

如果都能显示版本号，就可以继续。建议使用 JDK 17 或更新的版本；如果提示找不到 Java，可以到 Eclipse Temurin 下载页下载并安装适合自己电脑的 JDK。Mac 用户安装时留意处理器类型，安装完成后重新打开终端，再运行上面两条命令。

接下来新建一个专门放练习的目录，并进入它：

mkdir -p ~/java-practice
cd ~/java-practice

用编辑器新建 Hello.java，写入下面的内容：

public class Hello {
    public static void main(String[] args) {
        System.out.println("你好，Java！");
    }
}

保存后，在刚才的终端里运行：

javac -encoding UTF-8 Hello.java  # 把源代码编译成 Hello.class
java Hello                       # 运行这个程序，不要加 .java

如果看到“你好，Java！”，说明程序跑通了。main 是这个小程序的入口，Java 从这里开始执行；println 把内容输出到屏幕。现在不必急着记住每个词。

后面怎么运行？ 每个例子的标题都会写文件名。把代码单独保存到该文件中，然后像刚才一样运行 javac -encoding UTF-8 文件名.java，再运行 java 文件名（不带 .java）。不要把不同示例的代码拼进同一个文件。
先别急着往下学

一份 Java 程序，到底是怎么组成的？

刚才我们运行了 Hello.java。但你可能还有一个疑问：为什么代码要放在 class 里？main 那一长串又是做什么的？我们把程序拆开看看。

先看整体：从外到里有三层

Hello.java                 一个源代码文件
└── class Hello             文件中的一个类
    └── main 方法          程序启动时执行的入口
        └── 一条条语句     比如打印一句话

可以把类想成一个用来组织代码的盒子，方法是盒子里的一组动作。我们直接从终端启动这个小程序时，Java 会找到指定类中的 main 方法，从里面开始执行。

第一层：文件和类

先重新看这个完整例子，文件名是 Hello.java：

public class Hello {
    public static void main(String[] args) {
        System.out.println("你好，Java！");
    }
}

第一行的 class Hello 是在定义一个叫 Hello 的类。紧跟着的 { 表示类的内容从这里开始；最后的 } 表示结束。中间的 main 就在这个类里面。

这里类名前面有 public，因此文件要叫 Hello.java：类名和文件名必须一致，大小写也要一致。一个源文件里可以有多个类，但最多只能有一个 public 的顶层类。

第二层：main 方法

再看这行：

public static void main(String[] args) {

它是在定义一个叫 main 的方法。先把它当作 Java 启动普通命令行程序时约定好的入口，暂时照这个写。你也可以先认识每一部分：

写法现在可以这样理解
public允许外部访问，Java 启动程序时才能调用它。
static属于类本身；启动时不需要先创建 Hello 对象。
void这个方法执行完不会返回一个值。
main方法名；作为入口时要写对这个名字。
String[] args接收启动程序时传进来的文字参数；没有参数也要保留这个写法。

方法后面的 { ... } 圈出它要执行的内容。类有一对花括号，方法里面又有一对；就像大盒子里放了一个小盒子。缩进帮助人看清层次，但真正划分范围的是花括号。

第三层：方法里的语句

System.out.println("你好，Java！");

这是一条语句：让程序在终端打印引号里的文字，打印后换行。双引号表示这里是一段文字；末尾的分号 ; 表示这条语句结束。

我们可以再加一条：

public class Hello {
    public static void main(String[] args) {
        System.out.println("你好，Java！");
        System.out.println("今天开始学习。");
    }
}

再次运行时，程序会从上到下执行这两条语句，终端出现两行文字。

方法不只有 main

当一段动作需要多次使用时，可以给它单独起个名字。下面是一个完整例子，请保存为 Greeting.java：

public class Greeting {
    public static void main(String[] args) {
        sayHello("小明");
        sayHello("小红");
    }

    static void sayHello(String name) {
        System.out.println("你好，" + name + "！");
    }
}

这个类里有两个方法：main 和 sayHello。程序从 main 进入，执行 sayHello("小明") 时，文字“小明”被交给 name，然后打印“你好，小明！”。第二次用同样的方式打印“小红”。

String name 表示这个方法接收一段文字，称为参数；+ 在这里把几段文字拼起来。sayHello 写在 main 的后面也没关系：Java 先认识类中的方法，运行时仍然从 main 开始。

一份文件里，还可能看见 import 和 package

等你读到后面的集合示例，会看到这样的结构：

import java.util.ArrayList;
import java.util.List;

public class ShoppingList {
    public static void main(String[] args) {
        List<String> items = new ArrayList<>();
        items.add("苹果");
        System.out.println(items);
    }
}

这是一个完整例子，保存为 ShoppingList.java 可以运行。List 和 ArrayList 是 Java 已经提供的工具，开头的 import 告诉编译器我们要使用哪些类；后面的章节会仔细讲它们。不是每个文件都需要 import，比如之前的 Hello.java 就没有。

有些项目还会在文件最上方写 package，用来表明这个类属于哪个包，可以把包暂时想成给代码分类的名字。我们现在练习的小程序先不写 package，后面做项目时再结合目录学习。

从代码到运行，中间发生了什么？

Hello.java → javac 编译 → Hello.class → java 运行 → 终端输出

以没有写 package 的 Hello.java 为例，在文件所在的目录执行：

pwd                              # 看当前在哪个目录
ls                               # 确认能看到 Hello.java
javac -encoding UTF-8 Hello.java # 编译源代码
ls                               # 编译成功后通常能看到 Hello.class
java Hello                       # 运行 Hello 类

javac 读取你写的 .java 文件，检查语法并生成 .class 文件。这个文件里是 Java 字节码，可以交给 Java 虚拟机运行。随后 java Hello 找到 Hello 类，启动它的 main 方法。

文件名要分清：编译时写 Hello.java，因为交给 javac 的是源文件；运行时写 Hello，因为告诉 java 的是类名。终端所在目录不对时，可以先用 cd 进入保存文件的目录。

碰到报错，先看这几处

看到的问题可以先检查
找不到 Hello.java用 pwd 和 ls 检查当前目录，确认文件已经保存且名称正确。
提示 public 类应放在同名文件中确认 public class Hello 对应的文件名是 Hello.java。
编译时提示语法错误先看提示的行号，再检查引号、分号和花括号有没有配对。
找不到或无法加载主类先确认编译成功、当前目录有 Hello.class；运行命令写 java Hello。

08 / JAVA 入门

先认识一条任务

想想一条待办事项需要什么：一个标题，以及它是否已经完成。我们可以先把这些信息放到一起。

8.1 类与对象：先画样子，再创建一条任务

把下面的代码保存为 TaskDemo.java：

class Task {
    String title;
    boolean done;

    Task(String title) {
        this.title = title;
        this.done = false;
    }

    void complete() {
        done = true;
    }
}

public class TaskDemo {
    public static void main(String[] args) {
        Task task = new Task("学习 Java");
        System.out.println(task.title + "：" + task.done);
        task.complete();
        System.out.println(task.title + "：" + task.done);
    }
}

运行后，先看到 学习 Java：false，再看到 学习 Java：true。我们做了什么？class Task 描述任务有哪些数据和能做什么；new Task("学习 Java") 按这个描述创建一条具体任务；complete() 把它标记为完成。

类是描述，对象是创建出来的具体东西。title 和 done 是对象保存的数据；complete 是它能做的事，也叫方法。Task(String title) 是创建对象时调用的构造方法，this.title 指当前对象的标题，右边的 title 是传进来的值。

8.2 权限：哪些地方可以访问？

想象任务有一个重要的截止日期，不希望别的代码随手改成不合理的值。这时可以把数据藏起来，只留受控制的入口：

class Deadline {
    private int days;

    public void setDays(int days) {
        if (days >= 0) {
            this.days = days;
        }
    }

    public int getDays() {
        return days;
    }
}

这是一个片段，用来认识写法：private 表示只能在这个类内部直接访问；public 表示其他代码也可以访问。外部通过 setDays 修改，可以先检查数字；通过 getDays 读取。还有 protected 和不写修饰符的情况，先记住实际阅读时留意访问范围即可。

8.3 继承、多态与接口：同一个动作，不同做法

完成任务后，我们也许想提醒自己：一种提醒打印在终端，另一种提醒发送到别处。先规定“提醒”这件事，再让不同类各自实现它。

保存为 NoticeDemo.java：

interface Notifier {
    void send(String message);
}

class ConsoleNotifier implements Notifier {
    public void send(String message) {
        System.out.println("终端提醒：" + message);
    }
}

class QuietNotifier implements Notifier {
    public void send(String message) {
        System.out.println("安静记录：" + message);
    }
}

public class NoticeDemo {
    static void remind(Notifier notifier) {
        notifier.send("喝杯水");
    }

    public static void main(String[] args) {
        remind(new ConsoleNotifier());
        remind(new QuietNotifier());
    }
}

接口 Notifier 约定了 send 这个动作；两个类通过 implements 给出不同做法。remind 只要求拿到一个 Notifier，传入不同对象时，就会执行各自的 send。这就是这里的多态：相同的调用方式，可以对应不同实现。

继承则是从一个已有类出发，复用和扩展它。抽象类适合放一些共同的数据或行为，同时留下需要子类自己完成的部分。例如：

abstract class TaskBase {
    String title;
    TaskBase(String title) { this.title = title; }
    abstract void show();
}

class SimpleTask extends TaskBase {
    SimpleTask(String title) { super(title); }
    void show() { System.out.println(title); }
}

extends 表示继承；super(title) 调用父类的构造方法。抽象类不能直接 new TaskBase(...)，这里要创建的是 SimpleTask。接口更侧重约定能做什么；抽象类还可以集中放子类共用的状态和实现。

8.4 枚举：给有限的选项起名字

如果任务状态只允许“待办、已完成”，就不用到处手写字符串：

enum Status { TODO, DONE }
Status status = Status.TODO;  // 在方法中使用
System.out.println(status);   // TODO

这也是片段。枚举把固定选项列出来，代码里使用 Status.TODO，就不容易把状态写错。

8.5 异常：出错时程序怎么告诉我们

例如用户输入的天数应该是数字，却输入了“明天”。Java 可以用异常表示这次操作失败，我们也可以接住异常，给出更容易理解的提示。

保存为 ExceptionDemo.java：

public class ExceptionDemo {
    public static void main(String[] args) {
        String input = "明天";
        try {
            int days = Integer.parseInt(input);
            System.out.println("还有 " + days + " 天");
        } catch (NumberFormatException e) {
            System.out.println("请输入数字，例如 3。");
        } finally {
            System.out.println("输入检查结束。");
        }
    }
}

try 放可能出错的操作；匹配到 NumberFormatException 时执行 catch；finally 通常用于收尾。把 input 改成 "3" 再运行，看看变化。

读代码时还会看到 throws：它写在方法声明上，表示方法可能把异常交给调用方处理。Java 中有些异常要求编译时处理或声明，例如文件读写的 IOException；RuntimeException 及其子类通常不强制这样做。遇到异常先读类型和消息，找到出错行，再决定怎么处理。

08 / JAVA 入门

任务多了，放在哪里？

一条任务可以存在一个变量里。十条呢？我们需要一个容器来装它们。Java 常用的容器有 List、Set 和 Map。

容器适合装什么例子
List按顺序排列的东西，可以重复待办清单
Set不想重复的东西任务标签
Map通过一个键找到对应的值任务编号 → 任务标题

8.6 List、Set 与 Map

保存为 CollectionDemo.java：

import java.util.ArrayList;
import java.util.HashMap;
import java.util.HashSet;
import java.util.List;
import java.util.Map;
import java.util.Set;

public class CollectionDemo {
    public static void main(String[] args) {
        List<String> tasks = new ArrayList<>();
        tasks.add("喝水");
        tasks.add("学习 Java");
        tasks.add("喝水");
        System.out.println(tasks);  // 保留顺序，也保留重复项

        Set<String> tags = new HashSet<>();
        tags.add("学习");
        tags.add("学习");
        System.out.println(tags.size());  // 1

        Map<Integer, String> names = new HashMap<>();
        names.put(1, "喝水");
        names.put(2, "学习 Java");
        System.out.println(names.get(2));  // 学习 Java
    }
}

List<String> 里的 <String> 叫泛型：告诉 Java 这个列表装字符串。Map<Integer, String> 则表示键是整数、值是字符串。这样类型不匹配时，编译器就能帮我们发现很多错误。

HashSet 和 HashMap 不保证按添加顺序显示。常见的做法是用接口类型（如 List）声明变量，用具体实现（如 ArrayList）创建对象。

8.7 HashMap 为什么能按键查找？

可以把它想成一排抽屉：给定一个键，HashMap 会利用这个键的哈希值找到可能的位置，再用相等性判断确认是不是要找的键。不同键可能算到同一个位置，这叫哈希冲突，它会进一步区分这些键。

所以，如果自己写的类要作为 HashMap 的键，通常需要正确配合实现 equals 和 hashCode：判断相等的对象必须有相同的哈希值。普通字符串和整数已经提供了这些行为。

8.8 遍历：一个一个看

最直观的遍历方式是 for-each：

for (String task : tasks) {
    System.out.println(task);
}

如果遍历时还需要删除，可以使用迭代器。下面是一个独立程序，保存为 IteratorDemo.java：

import java.util.ArrayList;
import java.util.Iterator;
import java.util.List;

public class IteratorDemo {
    public static void main(String[] args) {
        List<String> tasks = new ArrayList<>(List.of("喝水", "休息", "学习"));
        Iterator<String> it = tasks.iterator();
        while (it.hasNext()) {
            String task = it.next();
            if (task.equals("休息")) {
                it.remove();
            }
        }
        System.out.println(tasks);  // [喝水, 学习]
    }
}

hasNext() 看还有没有下一项；next() 取出下一项；it.remove() 删除刚取出的项。遍历普通集合时直接调用集合的 remove，可能触发 ConcurrentModificationException；名字里虽然有“并发”，单线程中这样修改也可能遇到。

从清单里挑出想要的任务

假设你只想看包含“学习”的任务。除了写循环，Java 也提供了一种把“怎么筛选”写得更紧凑的方式。

8.9 Lambda：把一个小动作交出去

保存为 StreamDemo.java：

import java.util.List;
import java.util.Optional;

public class StreamDemo {
    public static void main(String[] args) {
        List<String> tasks = List.of("学习 Java", "喝水", "学习 Git");
        List<String> result = tasks.stream()
                .filter(task -> task.contains("学习"))
                .toList();
        System.out.println(result);

        Optional<String> first = tasks.stream()
                .filter(task -> task.contains("Docker"))
                .findFirst();
        System.out.println(first.orElse("没有找到"));
    }
}

先看 task -> task.contains("学习")：箭头左边是拿到的一条任务，右边是对它做的判断。它的意思可以读作“给我一条 task，看看它是否包含学习”。这种简短地描述一个动作的写法叫 Lambda。

8.10 Stream：一步一步处理

再顺着整条代码读：从 tasks 创建一个 Stream；filter 只留下符合条件的项；toList() 把结果收集成列表。因此第一行输出包含两条学习任务。原来的 tasks 没被这段筛选修改。

常见的还有 map（把每一项变成另一种形式）和 count（计数）。例如 tasks.stream().filter(t -> t.contains("学习")).count() 的结果是 2。这里的 toList() 需要 Java 16 或更新版本，因此前面建议使用 JDK 17 或更新版本。

8.11 Optional：结果可能没有

第二次筛选找不到 Docker。findFirst() 返回 Optional，表示结果可能有，也可能没有。orElse("没有找到") 表示有值就取值，没有就用这句提示。所以第二行输出“没有找到”。

08 / JAVA 入门

关掉程序后，怎么留下任务？

现在任务都存在程序内存里，程序结束后就没了。把它们写进文件，下次就能再读回来。

8.12 先写入，再读出

保存为 FileDemo.java，在练习目录中运行：

import java.io.IOException;
import java.nio.charset.StandardCharsets;
import java.nio.file.Files;
import java.nio.file.Path;
import java.util.List;

public class FileDemo {
    public static void main(String[] args) {
        Path file = Path.of("tasks.txt");
        List<String> tasks = List.of("学习 Java", "喝水");
        try {
            Files.write(file, tasks, StandardCharsets.UTF_8);
            List<String> saved = Files.readAllLines(file, StandardCharsets.UTF_8);
            for (String task : saved) {
                System.out.println(task);
            }
        } catch (IOException e) {
            System.out.println("文件读写失败：" + e.getMessage());
        }
    }
}

Path 描述文件位置；Files.write 写入多行文本；Files.readAllLines 一次读回所有行。UTF_8 指明文字编码，让中文按同一种方式写入和读取。这里的相对路径 tasks.txt 是相对于你运行命令时所在的目录。

留意：这个示例每次运行都会覆盖练习目录里的 tasks.txt。先确认那里没有需要保留的同名文件。

8.13 字节流和字符流有什么区别？

文件在底层是一串字节。处理图片、压缩包等原始数据时，通常用字节流；处理文字时，可以用理解文字编码的字符流。把字符变成字节、或者反过来，都需要知道编码方式，比如 UTF-8。

文件很大时，不一定要一次读完。BufferedReader 可以一行一行读；try (...) 会在用完后自动关闭读取器：

try (BufferedReader reader = Files.newBufferedReader(file, StandardCharsets.UTF_8)) {
    String line;
    while ((line = reader.readLine()) != null) {
        System.out.println(line);
    }
} catch (IOException e) {
    System.out.println("读取失败：" + e.getMessage());
}

这是片段：要放在方法内部，并引入 java.io.BufferedReader 等类型，file 可以沿用上面的 Path。readLine() 读到文件末尾时返回 null，循环就结束。

8.14 序列化：把数据变成能保存或传输的形式

一个任务对象住在程序内存里；想存进文件或发送给另一个程序，需要先把它转成双方能理解的格式，这个过程通常称为序列化。把保存的数据重新变回程序里的数据，则叫反序列化。

例如，把任务写成 JSON：{"title":"喝水","done":false}。项目之间交换数据经常使用 JSON；Java 自带的对象序列化也是一种机制。这里先记住用途，等写接口时再结合实际格式动手。

框架怎么知道你的类里有什么？

你可能见过：写一个类、加几个标记，框架就能识别它。这里面常会用到反射和注解。先通过一个很小的例子看它们各做什么。

8.15 反射：运行时查看类的信息

保存为 ReflectionDemo.java：

import java.lang.reflect.Method;

class Greeting {
    public void sayHello() {
        System.out.println("你好！");
    }
}

public class ReflectionDemo {
    public static void main(String[] args) throws Exception {
        Class<Greeting> type = Greeting.class;
        Method method = type.getMethod("sayHello");
        Greeting greeting = new Greeting();
        method.invoke(greeting);
    }
}

Greeting.class 拿到这个类的描述；getMethod("sayHello") 查找公开方法；invoke 在对象上调用它，最终输出“你好！”。这里用 throws Exception 把可能发生的异常交给调用方，方便集中看反射过程。

平时我们完全可以直接写 greeting.sayHello()。框架之所以需要反射，是因为它往往要处理你以后才写出来的类：在运行时查看类有哪些信息、按规则创建对象或调用方法。

8.16 注解：给代码加一个标记

你可能见过 @Override。把它写在方法上，表示这个方法要重写父类或接口中的方法，编译器会帮忙检查：

class Animal {
    void speak() { System.out.println("动物发声"); }
}
class Dog extends Animal {
    @Override
    void speak() { System.out.println("汪"); }
}

注解可以理解为附在代码上的额外信息。@Override 由编译器检查；框架中的某些注解则会在运行时被框架读取，例如用来标记某个类应由框架管理。不同注解的作用要看它的定义；写上标记之后，仍然需要相应的编译器、工具或框架去识别和处理它。
