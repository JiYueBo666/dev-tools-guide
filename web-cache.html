第二课：没变化的东西，为什么还要下载？

任务页面的样式和图标没有变。每次刷新都重新下载，会花掉时间和网络流量。

浏览器可以把收到的资源暂时保存起来，下次直接使用。这就是缓存。它带来一个新问题：什么时候可以继续用旧的，什么时候要问服务器？

1. 先给副本一个可直接使用的期限

Cache-Control: public, max-age=30

这条响应头表示响应可以被共享缓存保存，新鲜期为 30 秒。浏览器在副本仍新鲜时，可以直接使用它，不必再次向服务器请求完整内容。国内教程常把这种直接使用新鲜副本的情况称为“强缓存”。实际缓存还会考虑响应年龄，不能把所有情况都简单理解为从当前刷新起再计时。

在实验服务运行时，打开 http://127.0.0.1:8081/tips。打开 Network 面板，保持 Disable cache 未勾选，然后通过普通链接再次访问这个地址。你可能看到 from memory cache 或 from disk cache。刷新、强制刷新和开发者工具可能改变缓存行为，因此同时观察请求头中的条件字段和响应码。

2. 过了期限，就一定要重新下载吗？

假设副本过期了，但内容实际上没变。服务器可以只告诉浏览器“你手里的版本仍然有效”。为此，服务器给内容一个版本标记，叫 ETag。

第一次响应：
HTTP/1.1 200 OK
Cache-Control: public, max-age=30
ETag: "tips-v1"

先理解一次请求，再背协议名称。

以后验证时的请求：
GET /tips HTTP/1.1
If-None-Match: "tips-v1"

If-None-Match 可以读作：“如果和我这个版本不同，请给我新内容。”服务器发现版本相同，就返回 304，通常不带正文；浏览器复用已有副本。版本不同则返回 200 和新正文、版本标记。这种先询问再复用的做法常叫“协商缓存”。

3. 亲自比较 200 和 304

curl -i http://127.0.0.1:8081/tips
curl -i http://127.0.0.1:8081/tips -H 'If-None-Match: "tips-v1"'

第一条应返回 200 和文字。第二条应返回 304，没有那段正文。curl 这两条命令是在手动模拟验证，它没有像浏览器那样自动维护这份缓存。实验中的版本号是固定的；真实服务要在资源变化时生成对应的新标记。

先想一想

304 能减少什么？还需要访问服务器吗？

展开解释

需要访问服务器做验证，但通常无需重复传输正文。直接使用新鲜缓存，才可能连这次网络验证也省掉。

4. no-cache 和 no-store 为什么容易认错？

no-cache 允许保存，但再次使用前需要验证。它适合“可以留副本，但每次要确认”的情况。no-store 要求不要存储这个响应。private 表示只允许用户自己的私有缓存保存，不允许共享缓存保存。

带内容指纹的样式文件，例如 app.a81f.css，文件变化后地址也变，可以使用较长缓存。登录后的个人任务包含私有数据，需要按业务谨慎设置；本课实验的任务接口直接使用 no-store。不能把每个人的任务列表随意放进公用缓存。

5. 为什么改了代码，网页还像没变？

先看正在看的资源地址，再看 Cache-Control、ETag 和请求是否真正发出。若地址没变、缓存仍新鲜，浏览器可能正在使用旧副本。开发时可临时勾选 Disable cache；正式发布时则应设计合适的缓存策略和版本地址。
