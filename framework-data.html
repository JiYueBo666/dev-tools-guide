把内存里的任务交给数据库

重启后列表清空，说明任务仍只住在程序内存里。现在把保存责任交出去。

你已经用 JDBC 和 MySQL 保存过任务。Spring 不会改变数据库的基本工作，只会帮你管理连接、组织对象，并提供更少重复代码的访问方式。

先保持现有 MySQL 项目不动。框架数据库练习应使用独立数据库，例如 todo_framework_lab，并配置专用账号。示例下载包仍是内存版本，这一篇中的代码与配置是在旁边扩展时要加的部分。

连接为什么可以借来再归还

以前每次 DriverManager.getConnection 都可能新建连接，用完关闭。并发请求多时，反复建立连接会带来成本。连接池先管理一组连接，请求需要时借用，用完归还，后面的请求再复用。

Java 用 DataSource 提供这类连接入口。Spring Boot 常用 HikariCP 管理连接池。使用 JDBC 或 Data JPA starter 时通常会自动带上它，创建和回收过程由框架协助。

连接池不是越大越好。数据库能处理的连接有限，多个应用实例的连接还要相加。可先从小规模练习值开始：

spring:
  datasource:
    url: ${DB_URL}
    username: ${DB_USER}
    password: ${DB_PASSWORD}
    hikari:
      maximum-pool-size: 5
      minimum-idle: 1
      connection-timeout: 3000
      max-lifetime: 1500000

这段放在 application.yaml 的数据库配置中。最多 5 条连接，空闲时至少保留 1 条；借不到连接时最多等待 3000 毫秒；max-lifetime 控制连接在池中的最长寿命，常规情况下使用中的连接不会被强行中断，而是在归还后按规则回收。参数需要配合数据库和网络的超时限制，示例数字不是所有项目的标准答案。

用完连接必须关闭，在池化场景下 close 通常表示归还给池。长时间占着连接、查询过慢或事务过大，都会让后续请求排队。

从自己写 SQL，到让映射工具帮忙

如果继续使用熟悉的 SQL，可以先用 Spring JDBC/JdbcTemplate；它帮你管理重复的连接与异常处理。想进一步用 Java 对象表达表中的记录，可以使用 JPA 与 Hibernate。JPA 是一套持久化约定，Hibernate 是常用实现，Spring Data JPA 又提供便捷的 Repository 接口。

这一步对应图片里 GORM 所解决的对象与数据表映射问题。需要在 pom.xml 增加 spring-boot-starter-data-jpa 和运行时 mysql-connector-j，版本交给本示例的 Spring Boot 依赖管理。可从 数据库官方文档查依赖与配置。

给一条任务标明怎样保存

新建独立的 TaskEntity.java，放在 com.example.todo 包中。下面是一个完整的实体类，需要已经加入 JPA 依赖：

package com.example.todo;
import jakarta.persistence.*;

@Entity
@Table(name="tasks")
public class TaskEntity {
    @Id
    @GeneratedValue(strategy=GenerationType.IDENTITY)
    private Long id;
    @Column(nullable=false, length=200)
    private String content;
    @Column(nullable=false)
    private boolean done;

    protected TaskEntity() {}
    public TaskEntity(String content) { this.content = content; }
    public Long getId() { return id; }
    public String getContent() { return content; }
    public boolean isDone() { return done; }
    public void finish() { done = true; }
}

@Entity 让映射工具知道它对应可持久化的数据，@Table 指定表名。@Id 标识编号，IDENTITY 使用数据库生成编号。protected 无参数构造方法供持久化工具创建对象。业务则通过有内容的构造方法创建新任务。

再在 TaskRepository.java 声明：

package com.example.todo;
import org.springframework.data.jpa.repository.JpaRepository;
import java.util.List;

public interface TaskRepository extends JpaRepository<TaskEntity, Long> {
    List<TaskEntity> findByDoneFalseOrderByIdAsc();
}

Spring Data 根据接口准备实现，继承来的 save、findById、delete 等承担基础操作。这个长方法名表达“找未完成任务，按编号升序”。复杂查询仍可能需要显式 JPQL 或 SQL，框架没有替你消除理解查询的需要。

接回 service 时，事务放在哪里

创建任务时，service 可以调用 repository.save(new TaskEntity(content))。完成任务时，service 按 id 找实体，找不到抛出业务异常，找到后调用 finish。把这一整个业务过程放到 Spring 管理的 @Transactional 方法里，在同一事务中完成；受管理实体的变化会在提交前同步到数据库。

Controller 继续返回专门的响应数据，不直接把带关联和内部字段的实体全部暴露出去。这样数据库表变化时，接口不必跟着泄露每个细节。

初始化数据库时要明确由谁建表。练习可在专用库中使用 ddl-auto: update 理解现象；长期项目应使用 Flyway/Liquibase 等版本迁移，并常用 validate 检查映射。不要把 create 或 create-drop 配到已有任务数据库上。
