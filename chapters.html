02 / 版本管理

Git：让每一次修改都有记录

代码改坏了，怎么回到之前的版本？两个人改了同一个文件，又该怎么合在一起？

Git 记录项目在不同时间的快照。你先在自己的电脑上修改和提交，再按需推送到 GitHub。我们先在一个单独的练习目录里走一遍，后面再看协作。

修改文件 → 暂存 add → 提交 commit → 推送 push

2.1 创建仓库，保存第一个版本

在终端依次运行：

mkdir ~/git-practice
cd ~/git-practice
git init
printf '# 学习笔记\n' > notes.md
git status
git add notes.md
git commit -m "添加学习笔记"
git log --oneline

git init 让当前目录成为 Git 仓库；git status 查看当前状态；git add 把要提交的修改放进暂存区；git commit 保存一次快照。提交信息应该让你之后看得懂这次做了什么。

如果首次提交提示身份未配置，根据终端提示配置 user.name 和 user.email 后重试。提交前可以用 git diff 查看尚未暂存的修改，用 git diff --staged 查看已暂存、准备提交的修改。

2.2 用分支尝试新内容

你想增加一节笔记，但还没有决定是否保留。分支可以让你先在独立的工作线上修改，确认后再合回主分支。

git branch --show-current    # 记住当前分支名称
git switch -c add-git-notes
printf '\nGit 用来记录版本。\n' >> notes.md
git diff
git add notes.md
git commit -m "补充 Git 笔记"
git switch main              # 如果原分支不是 main，换成刚才看到的名称
git merge add-git-notes
git log --oneline --graph --all

git switch -c 创建并切换分支；git merge 将指定分支的修改合入当前分支。先切回主分支，再执行合并。

2.3 冲突发生时怎么办？

如果两个分支修改了同一个文件的同一处，Git 可能无法判断保留哪一版。此时运行 git status 找到冲突文件，在编辑器中查看：

<<<<<<< HEAD
当前分支的内容
=======
准备合入分支的内容
>>>>>>> add-git-notes

和协作者确认需要保留的内容，编辑文件并删除这些标记，再执行 git add 文件名 和 git commit。如果想放弃尚未完成的本次合并，可以用 git merge --abort 回到合并前状态。

2.4 GitHub：推送、拉取与 PR

在 GitHub 上创建一个空仓库后，按仓库页面给出的地址关联远程仓库并推送：

git remote add origin https://github.com/你的用户名/仓库名.git
git push -u origin main

地址要替换成你自己的仓库地址；如果主分支不是 main，换成实际名称。以后同一分支通常可以直接用 git push。在另一台电脑上下载仓库用 git clone 仓库地址；获取并整合远程更新常用 git pull。拉取前先用 git status 看看本地是否有未提交修改。

Pull Request（PR） 是请求把一个分支的修改合入另一个分支。把练习分支推送后，在 GitHub 仓库页面选择该分支，点击 Compare & pull request，检查目标分支、差异和说明，再创建 PR。页面上的 Files changed 就是给审阅者看的差异。

2.5 哪些文件不提交？

在仓库根目录创建 .gitignore，列出不需要追踪的文件，例如：

.DS_Store
__pycache__/
.env

.gitignore 对尚未被 Git 追踪的文件生效；已经提交过的文件不会因为新增规则自动消失。不要把密码、令牌等敏感信息提交到仓库。

练习 / 动手做一次

提交并合并一条笔记

  1. 在练习仓库创建分支，修改笔记，用 diff 查看变化。
  2. 提交后合并回主分支，再用 log 看看记录。
  3. 有 GitHub 仓库时，将分支推送并创建一次 PR，观察 Files changed。
03 / 编辑器

编辑器：找到代码为什么这样运行

面对一个陌生项目，你可能会问：这个函数在哪里定义？变量运行到这里到底是什么值？编辑器可以帮你沿着代码找到答案。

下面用 VS Code 和 Python 举例；如果你使用 Go 或 Java，也可以在对应语言插件或 IDE 中完成同样的操作。先安装 VS Code 的 Python 扩展，并确认电脑能运行 python3。

3.1 跳转定义与格式化

新建 debug_demo.py：

def total(prices):
    return sum(prices)

items = [12, 25, 8]
result = total(items)
print(result)

在 total(items) 上右键选择“转到定义”，编辑器会跳到函数定义处。右键选择“格式化文档”，可以使用已配置的格式化工具整理代码；如果提示选择格式化程序，先按编辑器提示安装或选择一个。

3.2 用断点观察变量

  1. 在 result = total(items) 这一行左侧点击，出现红点，即设置断点。
  2. 打开“运行和调试”，选择运行当前 Python 文件；程序会在这一行执行前暂停。
  3. 在变量面板查看 items，再用“单步跳入”进入 total，查看参数 prices。
  4. 用“继续”让程序运行到结束，终端应输出 45。
要点：断点让你暂停程序；单步让你观察程序如何往下走。排查问题时，先在你想验证的位置停下，再看变量。
练习 / 看懂数据流

增加一个价格

把 items 改成 [12, 25, 8, 5]，重新调试。进入函数后，prices 是什么？最终输出是多少？

04 / 数据格式

数据格式：让程序交换信息

接口返回的数据、项目配置和项目说明，分别适合用不同格式。我们先认识开发中最常见的三种：JSON、YAML 和 Markdown。

4.1 JSON：接口里的数据

{
  "name": "学习计划",
  "completed": false,
  "topics": ["Git", "Docker"],
  "owner": { "name": "小明", "level": 1 }
}

大括号表示对象，方括号表示数组。这里 topics 是字符串数组，owner 是嵌套对象。JSON 的键和字符串使用双引号；布尔值是 true、false，空值是 null。最后一项后面不要多写逗号。

用 Python 读取本地 JSON 的例子：

import json

with open("plan.json", encoding="utf-8") as f:
    plan = json.load(f)
print(plan["owner"]["name"])
print(plan["topics"][0])

把上面的 JSON 保存为 plan.json 后运行，输出分别是 小明 和 Git。写入可使用 json.dump(plan, f, ensure_ascii=False, indent=2)，并以写入模式打开文件。

4.2 YAML：容易阅读的配置

app:
  name: study-api
  port: 8000
  debug: false
  topics:
    - Git
    - Docker

YAML 用缩进表示层级：name 和 port 都属于 app；短横线表示列表项。同一层级要对齐，使用空格而不是 Tab 缩进。不同项目对字段名和含义的规定要看项目自己的配置说明。

4.3 Markdown：写给人看的说明

# 项目名称

这是项目的简短介绍。

## 启动步骤

1. 安装依赖
2. 启动服务

更多信息见 [项目地址](https://example.com)。

# 表示标题，数字加点表示有序列表，方括号和圆括号组合成链接。GitHub 仓库的 README 通常使用 Markdown，适合记录项目用途和启动方式。

练习 / 自己写

描述你的学习计划

写一个 JSON 对象：包含计划名称、是否完成、两个学习主题，以及一个包含姓名的 owner 对象。然后用 Markdown 写三行项目说明。

05 / 接口调试

接口调试：给服务发送一条请求

前端和后端如何交换数据？前端向一个地址发送 HTTP 请求，后端返回状态码和响应内容。调试接口时，我们也可以直接扮演客户端，看看服务实际返回了什么。

客户端发送请求 → 服务处理 → 返回状态码和响应体

5.1 一条请求里有什么？

部分作用
方法与 URL例如 GET 查询资源，POST 提交数据；URL 指向目标地址
Header附加信息，例如请求体格式、身份凭证
Body请求携带的数据，常用 JSON
状态码与响应体服务的处理结果和返回的数据

5.2 用 curl 发请求

终端中的 curl 可以发送 HTTP 请求。先向公开测试服务请求一条示例数据：

curl -i https://jsonplaceholder.typicode.com/posts/1

-i 会显示响应头和状态码。再试一次 POST，带上 JSON 请求体：

curl -i -X POST 'https://jsonplaceholder.typicode.com/posts' \
  -H 'Content-Type: application/json' \
  -d '{"title":"学习接口","body":"第一次请求","userId":1}'

-X POST 指定方法；-H 设置请求头；-d 提供请求体。这个公开服务返回模拟创建结果，不会持久保存新帖子。

5.3 Token 放在哪里？

需要登录的接口常用 Authorization 请求头携带身份凭证。下面只是格式示例，请替换成你自己的服务地址和令牌：

curl -i 'https://你的服务地址/api/me' \
  -H 'Authorization: Bearer 你的令牌'

令牌相当于登录凭证，不要提交到 GitHub，也不要发给不认识的人。实际接口使用什么认证方式，以该接口的说明为准。

5.4 在 Postman 或 Apifox 里做同样的事

  1. 新建请求，选择 POST，填入上面的测试服务地址。
  2. 在 Headers 填写 Content-Type: application/json。
  3. 在 Body 选择 JSON，填入示例请求体，然后发送。
  4. 查看响应的状态码、Headers 和 Body。需要 Bearer Token 时，可在 Authorization 中选择对应方式并填入令牌。
练习 / 对照观察

比较两次请求

分别发送 GET 和 POST，找出它们的方法、URL、状态码和响应体。POST 请求中的 title 出现在响应的哪里？

06 / 浏览器调试

Network：看网页背后发生了什么

网页上的按钮点了没反应，问题可能发生在请求发出之前，也可能发生在服务返回之后。浏览器的 Network 面板让你看到请求有没有发出，以及返回了什么。

6.1 捕捉请求

  1. 打开任意你有权限访问的网页，打开开发者工具：Mac 通常可按 Command + Option + I。
  2. 选择 Network 面板，然后刷新页面，让面板记录加载过程。
  3. 选择 Fetch/XHR 筛选接口请求；如果当前页面没有这类请求，可以先查看任意一条文档或资源请求。
  4. 点击一条请求，查看 Headers、Response 和 Timing；带请求体的请求还可查看 Payload。

6.2 先看哪几项？

位置要回答的问题
Headers请求发给了哪个 URL？方法和状态码是什么？
Payload提交了什么参数或请求体？
Response服务返回了什么？错误信息在哪里？
Timing时间主要花在连接、等待服务还是下载？

状态码可以作为排查入口：200 常表示成功，404 表示资源未找到，500 表示服务端发生错误。具体原因还要结合响应内容和服务日志判断。

要点：Network 面板里的请求头和响应可能包含个人信息或令牌。分享截图或复制请求前，先检查并遮住敏感内容。
练习 / 观察一条请求

从页面找到答案

打开本教程的 Network 面板并刷新。找一条请求，记录它的 URL、状态码和耗时。它是 HTML、样式文件，还是接口请求？

07 / 容器

Docker：几条命令启动 Redis 或 MySQL

项目需要 Redis，但你还没在电脑上安装它。Docker 可以用现成的镜像启动一个容器，让你先把服务跑起来。

可以先把镜像理解为启动服务所需的模板，容器理解为由镜像运行起来的实例。下面在 Mac 上使用 Docker Desktop：先安装并启动它，等 Docker 引擎运行后，在终端检查：

docker version
docker ps

如果连接不到 Docker daemon，先检查 Docker Desktop 是否已经启动。接下来只需先完成 Redis 实验，MySQL 可以作为第二次练习。

7.1 启动 Redis

docker run -d --name study-redis -p 127.0.0.1:6379:6379 redis:7

-d 让容器在后台运行；--name 指定名称；-p 127.0.0.1:6379:6379 将本机 6379 端口映射到容器内的 6379 端口，并只监听本机。首次运行需要下载镜像。

检查状态，再进入容器里的 Redis 客户端：

docker ps
docker logs study-redis
docker exec -it study-redis redis-cli

进入 redis-cli 后，输入：

PING
SET course "dev-tools"
GET course
EXIT

正常情况下，PING 返回 PONG，GET course 返回刚才写入的值。EXIT 退出客户端，不会停止容器。

7.2 停止和再次启动

docker stop study-redis
docker ps -a
docker start study-redis

docker ps 查看运行中的容器；docker ps -a 包含已经停止的容器。如果端口被占用，可以先用命令行章节的 lsof -i :6379 查找原因，或者改用空闲的本机端口，例如 -p 127.0.0.1:6380:6379。

7.3 再试一次 MySQL

下面是本机练习用的示例密码。请只用于练习环境：

docker run -d --name study-mysql \
  -e MYSQL_ROOT_PASSWORD=study_password \
  -p 127.0.0.1:3306:3306 mysql:8.0

MySQL 初始化需要一点时间。用 docker logs study-mysql 查看日志，等服务准备完成后进入客户端：

docker exec -it study-mysql mysql -u root -p

按提示输入刚才的密码，然后执行：

SELECT VERSION();
SHOW DATABASES;
EXIT;

如果本机 3306 已被占用，可以改用 -p 127.0.0.1:3307:3306。这些示例没有配置持久化卷：删除容器后，容器内的数据也会丢失。要长期保留数据，需要后续学习卷和备份。

练习 / 跑通服务

验证你的 Redis

  1. 启动 Redis，确认 docker ps 中能看到它。
  2. 用客户端执行 PING，确认返回 PONG。
  3. 停止容器，再用 docker ps -a 找到它。

完成后，你已经走通从启动服务到验证结果的完整流程。
