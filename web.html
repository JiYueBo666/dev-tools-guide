让浏览器也能使用任务清单

你已经能在终端里添加和查看任务。如果想用一个网页来操作，程序要怎样配合？

先想象一个很小的页面：上面有任务列表、输入框和“添加”按钮。用户输入“喝水”，按一下按钮，列表多出一项。网页需要把这句话交给你的 Java 程序，Java 再保存到数据库。保存成功后，网页还需要知道结果。

终端里，Scanner 接收输入，println 显示结果。换成网页后，浏览器负责输入和显示，Java 程序通过网络接收请求、返回结果。原来 TaskDao 里的数据库操作仍然有用。

以前：键盘 → Scanner → TaskDao → MySQL → 终端文字
现在：网页 → HTTP 请求 → Java 处理请求 → TaskDao → MySQL
      网页 ← HTTP 响应 ← Java 整理结果 ← 查询结果

这条路径里会遇到几件具体的事：双方怎么表达操作？页面刷新时是否要重新下载？登录后怎么认出用户？网页和接口地址不同怎么办？我们带着这些问题往下学。

阅读顺序带着什么问题读
第一课：一条任务怎么从网页发出去？HTTP、前后端分工、接口约定、JSON 与 REST
第二课：没变化的东西，为什么再下载？缓存、新鲜时间和版本验证
第三课：发请求前，电脑先做了什么？TCP、HTTPS、连接复用和 HTTP/2
第四课：终端能访问，网页为什么报错？同源策略、CORS 和预检
第五课：登录一次，为什么能记住我？Cookie、Session、Token 和 JWT
第六课：页面、接口和数据库，放在哪里？静态文件、Nginx、Servlet 和 Tomcat

先准备一个可以观察的实验

本课提供一个小服务，使用 JDK 自带的 HttpServer。它返回固定示例任务，并演示缓存和跨域。它不实现完整的任务增删改查。现在先用它看清请求过程，后面再把同样的接口思路接到你的 TaskDao。

下载 HttpPractice.java。把文件放进新建的练习文件夹，例如 ~/http-practice。需要 JDK 17 或更新版本，无需添加 Maven 依赖。

cd ~/http-practice
javac -encoding UTF-8 HttpPractice.java
java HttpPractice

看到两个地址后，保持终端运行。8080 提供网页，8081 提供接口。需要停止时按 Control + C。如果提示端口占用，先用 lsof -i :8080 和 lsof -i :8081 查找占用者。

后面所有 curl 命令都在另一个终端标签页中执行。浏览器实验使用 http://127.0.0.1，保持主机名一致，便于观察端口造成的跨域。
