从终端任务清单走向网页

把终端里的任务清单，放到网页上

你已经能在终端里记任务了。现在，想象我们给它换一张更方便使用的脸。

你打开一个网页，写下“下午三点交作业”，按一下“添加”。这句话出现在清单里。第二天重新打开网页，它仍然在。

看起来只是点了一个按钮，背后却有几个人在配合：网页接收你输入的文字，Java 程序处理这件事，MySQL 把任务留下来。我们接下来要讲的网络知识，就是为了让这几部分能顺畅地交谈。

从坐在电脑前，到隔着网络操作

你原来的程序像一个面对面办事的小窗口。Scanner 听你输入，TaskDao 把任务存好，println 当场把结果显示出来。输入和处理都在同一台电脑、同一个程序里，彼此直接调用方法就能配合。

换成网页以后，输入的地方变了。你可能坐在另一台电脑前，用浏览器打开页面。负责保存任务的 Java 程序，仍然运行在服务器上。它听不到你键盘上的声音，也看不到你点击了哪个按钮。

于是，网页需要把你的意思写成一份消息，发给 Java 程序。Java 处理完，再回一份消息。浏览器收到结果，把新的任务显示出来。这一来一回，就是接下来整部分内容的主线。

先跟着一条任务走

你输入“喝水”后，网页会把任务内容放进消息里，送到一个约定好的地址。Java 在这个地址等待请求，收到后检查文字是否合适，再调用你已经写好的 TaskDao。

TaskDao 把任务存进 MySQL。Java 随后告诉浏览器“添加成功，这是新任务的编号”。浏览器就能把这条任务放到列表中。用户不用知道数据库密码，也不用看到 SQL，只需要等待页面给出结果。

以后你想把页面从白色改成深色，可以改显示部分；想改变数据库里的保存方式，可以改后端处理。双方通过消息约定配合，这样就不必每次一起重写。

这些知识为什么会陆续出现

先要解决的是“消息怎么写”，所以第一篇讲 HTTP。接着会发现，同一张图标没有变化，反复下载很浪费，于是讲缓存。消息要到达远处，还涉及连接和通信保护，第三篇把这段路讲清楚。

等网页和接口放在不同地址，你可能发现浏览器不肯把结果交给网页。第四篇解释这个限制的来由。再往后，网站要分清你的任务和别人的任务，就需要登录凭证。最后，我们把页面、Java 和数据库放回一张图中，看看服务器怎样让它们各就各位。

有一个小程序，可以陪你读

文中提到的消息，可以在我们准备的实验程序里看到。它只提供固定任务、缓存和跨域演示，不连接你的数据库。下载 HttpPractice.java，放进 ~/http-practice 文件夹。使用 JDK 17 或更新版本，在这个目录运行：

cd ~/http-practice
javac -encoding UTF-8 HttpPractice.java
java HttpPractice

它会启动两个地址：8080 提供网页，8081 接收接口请求。终端保留运行，另开一个标签页输入后续命令。结束时按 Control + C。如果端口已被其他程序占用，可以用 lsof -i :8080 和 lsof -i :8081 查找占用者。你也可以先读正文，等需要看实际消息时再启动它。
