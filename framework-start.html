网页敲门，谁来接待？

打开一个地址，程序里某个方法就开始执行。这个连接是怎样建立的？

你以前的 Todo 等着人输入菜单编号，再用 switch 选择功能。网页接口也需要选择功能，只是选择依据换成了请求方法与路径。例如 GET /api/tasks 查列表，POST /api/tasks 添加任务。

Spring MVC 启动时会读取你给类和方法写的标记，把这些组合记下来。请求来了，它从这张对应表里找到处理方法。这张“哪种请求交给谁”的对应关系，就是路由。

先接一条最简单的查询

打开示例中的 src/main/java/com/example/todo/TaskController.java。文件顶部的 package 表示它属于哪个包，import 引入要用的框架类。先看类上的两个标记：

@RestController
@RequestMapping("/api/tasks")
public class TaskController {
    // 请求处理方法放在这里
}

@RestController 让 Spring 识别这类请求处理组件，并把方法返回值写入响应正文。@RequestMapping 给这里的请求约定共同前缀 /api/tasks。相近功能放在同一前缀下，相当于图片中的 Group 分组。它不自动提供登录保护，共同规则仍要配置。

类中的查询方法如下：

@GetMapping
public List<TaskService.Task> list(
        @RequestParam(defaultValue="false") boolean onlyOpen) {
    return service.list(onlyOpen);
}

@GetMapping 表示接收 GET，没有再写子路径，于是完整地址就是 /api/tasks。你请求 /api/tasks?onlyOpen=true 时，Spring 取出问号后面的 onlyOpen，转换成 boolean 交给方法；没有传时使用 false。这就是查询参数绑定。

方法调用 service.list，再把列表返回。框架会按已经配置好的消息转换器把数据写成 JSON。你不用在这个方法里再打开输出流、手动拼接 HTTP 头。

从整个列表，找到其中一条

列表里的每条任务都有编号。想查编号 3，可以让地址带上它：

@GetMapping("/{id}")
public TaskService.Task find(@PathVariable long id) {
    return service.find(id);
}

请求 /api/tasks/3 时，{id} 匹配路径中的 3，@PathVariable 把它交给 long id。查询参数适合补充筛选条件，路径参数适合指出当前要操作哪项资源。若写成 /api/tasks/abc，abc 无法转换成整数，示例会返回 400。

一条新任务怎样出现

先用这个请求添加任务，再用响应中的 id 查询它。示例进程刚启动且没有添加过任务时，首个 id 是 1：

curl -i http://127.0.0.1:8090/api/tasks   -H 'Content-Type: application/json'   -d '{"content":"学习 Spring Boot"}'

你会收到 201、Location 头和新任务 JSON。Location 指向新任务地址，接着 GET 这个地址就能看到它。路由已经不再由你手写 switch 分派，Spring 把 POST 交给 create，把 GET 交给 find 或 list。

示例里的其余请求是：PATCH /api/tasks/1/done 标记完成，DELETE /api/tasks/1 删除。查询 /api/tasks?onlyOpen=true 时，已完成的任务不出现在列表中。这些操作都能在下载的示例里运行。

main 还在，只是它启动的东西变了

查看 TodoApplication.java，仍然有你熟悉的 main。里面的 SpringApplication.run 会创建应用环境、准备对象并启动内置 Web 服务器。@SpringBootApplication 所在包是扫描其他组件的重要起点，所以示例把控制器和服务放在同一个根包下面。

以后仍可以通过 main 调试，只是程序启动后一直等待网络请求。原来的 Scanner 由 HTTP 入口接替，TaskDao 等业务与数据代码则可以逐步接回来。
