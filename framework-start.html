前面的内容

HTTP 与网页读懂已有代码
想先会用：进入 Spring Boot 工程速通，按文件位置、固定写法和验证命令完成项目。
先看懂你已经运行的程序

打开 /hello 以后，到底发生了什么？

你现在不用继续写代码。把运行着的程序想成一台已经开门营业的小机器，我们一起看它怎样接到一次请求，又怎样把文字送回来。

你写过终端程序：运行 main，遇到 Scanner 就等待键盘输入，输入后继续执行，最后把文字打印到终端。现在我们仍然有 main，只是输入从键盘换成了浏览器，输出也要送回浏览器。为了接收这些网络消息，程序里多了一套 Web 服务工具。

先把刚才做的事接成一条线

你在终端启动 Java 程序，它开始等待请求。接着，你在浏览器输入地址。浏览器把请求送到这台电脑的 8090 端口。程序收到后找到 hello 方法，执行它，拿到返回的文字，最后把文字发回浏览器。

浏览器访问 /hello
↓
8090 端口上的 Web 服务收到请求
↓
Spring 找到 HelloController 的 hello 方法
↓
方法返回“你好，任务清单”
↓
Web 服务把文字放进 HTTP 响应
↓
浏览器显示文字

先记住这条线。下面讲的配置、注解和类，都要放回这条线上，看看它们帮了哪一段忙。

为什么写好了 HelloController，还要有 main？

只在文件里写下一个方法，Java 不会自动执行它。你原来的程序也是从 main 进入，再由 main 调用其他方法。这一次，入口仍然在 TodoApplication.java：

public static void main(String[] args) {
    SpringApplication.run(TodoApplication.class, args);
}

main 开始执行后，调用 SpringApplication.run。这是 Spring Boot 提供的方法，你通过 Maven 加入的依赖里有它。这个调用会开始准备应用：读取配置、寻找组件、安排对象，启动内置的 Web 服务器。

TodoApplication.class 把“哪个类是这次应用的配置起点”交给 Spring。这里的 .class 表示取得这个类的描述对象，不是在写一个硬盘文件名。args 则继续传入启动程序时收到的命令行参数。

服务启动后，进程继续运行，等待之后到来的网络请求。hello 方法此时还不需要执行。等浏览器真正来访问，再由请求处理过程调用它。所以你启动时没有看到“你好，任务清单”，访问网页时才看到它。

地址里的每一段，把请求送到了哪里？

http://127.0.0.1:8090/hello

http 说明按 HTTP 方式交谈；127.0.0.1 指你当前这台电脑；8090 指这台电脑上接收请求的端口；/hello 告诉服务，这次想访问哪个路径。

可以把主机地址和端口想成先找到一栋楼及其中的接待处，再把 /hello 交给接待处选择具体服务。端口帮助网络消息找到正在接收它的程序，路径帮助这个程序分辨要处理什么。

因此，程序没启动，接待处还没开，就连接不上。程序在 8080 等待，你却去 8090，也连接不上。若已经找到服务，只是没有 /hello 这条路径，才可能得到 404。这些情况发生在不同位置。

你之前的 YAML 写成 port:8090，缺少冒号后的空格，端口设置没有按预期生效，程序用了默认的 8080。这正好说明：写进配置的内容，要被正确读取，才会影响正在运行的服务。

Spring 怎么知道 /hello 对应哪个方法？

回到 HelloController.java。先看完整的主要部分：

@RestController
public class HelloController {
    @GetMapping("/hello")
    public String hello() {
        return "你好，任务清单";
    }
}

hello 是方法名。/hello 是网络路径。它们恰好用了同一个词，但本来可以不同。真正把请求路径和方法连起来的是 @GetMapping("/hello")，它写明“GET 请求访问 /hello 时，调用下面这个方法”。

例如，把方法名 hello 改成 saySomething，保留 @GetMapping("/hello")，浏览器仍然访问 /hello。反过来，只把标记里的路径改成 /welcome，网络入口就变成 /welcome。这样就能分清方法名和网址路径各由谁决定。

这些以 @ 开头的写法叫注解。这里可以先把它理解成附在代码上的说明，Spring 会读取说明并据此安排工作。@RestController 告诉它，这个类参与 Web 请求处理，方法返回值要作为响应内容交出去；@GetMapping 进一步给出方法与路径的对应关系。

启动时，Spring 会建立请求与处理方法的对应关系。请求来到以后，就可以按方法和路径找到处理代码。你没有在 main 里手写 hello()，是因为调用的时机交给了 Web 请求处理过程。

那么，谁去发现这个类，又是谁创建它？

TodoApplication 上还有一个 @SpringBootApplication。它让这里成为启动配置的一部分，并启用组件扫描等安排。默认情况下，Spring 会从这个类所在的包向下查找合适的组件。

你的 TodoApplication 和 HelloController 都写着 package com.example.todo，所以 HelloController 在扫描范围内。Spring 识别到它是控制器，会准备相应对象。后面收到 /hello 请求，就在这个对象上执行方法。

这就是你没有写 new HelloController()，方法仍能被调用的原因：对象由框架管理了。框架能这样做，是因为你提供了启动入口、扫描范围和控制器标记，而不是单凭文件名猜用途。

import 的工作更早。它帮助 Java 编译器认出 SpringApplication、RestController 等短名称分别指哪个类。实际的类由 Maven 依赖提供，注解表达框架要读取的安排，启动时 Spring 再根据这些安排组织对象。这几件事分工不同，但都在同一条过程中。

return 后面的文字，怎么跑到了浏览器？

在普通 Java 方法里，return 把值交给调用者。这里也一样。hello 把字符串交还给调用它的 Spring MVC 请求处理过程。因为这个类使用 @RestController，框架把返回值交给合适的消息转换器，写到 HTTP 响应正文中。

对于这段字符串，浏览器拿到的就是一份文字响应，再把正文显示到页面上。如果你在方法里写 System.out.println，文字会出现在运行 Java 的终端；想让浏览器拿到文字，需要返回给框架，由框架写响应。

因此，“网页上出现文字”并不是 Java 方法直接操作了浏览器窗口。中间还有一份 HTTP 响应。浏览器收到它以后，才负责显示。这一层边界后面会继续帮我们理解 JSON 和页面渲染。

再回看几个文件，就能知道各自为何存在

pom.xml 让 Maven 知道需要 Spring Web 这一组工具。Maven 负责准备编译、启动所需的库。它不负责接收浏览器的每一次请求。

application.yaml 告诉应用使用 8090 端口。启动时读到配置，Web 服务才知道在哪里接待。main 发起启动，HelloController 则说明请求进来后由哪个方法处理。启动准备和请求处理，是先后发生的两段过程。

启动时：
Maven 准备依赖与运行环境
    → Java 执行 main
    → Spring 读取配置、发现控制器、安排对象
    → Web 服务开始等待请求

每次访问时：
浏览器发送 GET /hello
    → Web 服务接收
    → Spring 调用 hello
    → 返回文字 → HTTP 响应 → 浏览器显示

从这些文件回头看，你已经亲手完成了最小的 Web 应用：有启动入口，有接收请求的端口，有地址到方法的对应关系，也有一份回复。

后半页的任务列表，只是在这条线上多加一站

hello 方法可以直接返回固定文字。查询任务则需要去拿数据，所以控制器先调用 TaskService，再把得到的列表返回。构造方法接收的 service，就是它需要合作的对象。Spring 会先准备服务对象，再交给控制器。

你之后写到的 List、筛选和编号处理，仍然是普通 Java 代码。新的地方在外侧：由 HTTP 请求触发方法，再由框架整理响应。这一阶段 TaskService 只把任务留在内存里，尚未调用你的 MySQL。

你现在的项目中已有 /hello 这条路径，就先把这条路径理解透。页面后面的任务代码可以等需要扩展时再读，不必为了看懂一次浏览器访问，同时记住并发容器和 Stream 的写法。

从空文件夹写出第一个接口

我们先让浏览器显示一句“你好，任务清单”。先不连接数据库，也不创建任务。只把一条请求怎样进入 Java 讲清楚。

先给这个练习留一个地方

在终端创建新目录。原来的 javacode 项目保留，后面需要接数据库时再对照它。

mkdir -p ~/code/todo-web/src/main/java/com/example/todo
mkdir -p ~/code/todo-web/src/main/resources
cd ~/code/todo-web

src/main/java 是 Maven 查找 Java 源码的目录。后面的 com/example/todo 对应我们要写的包名 com.example.todo。src/main/resources 放应用读取的配置等资源。现在这些文件夹还是空的。

告诉 Maven：这个程序需要接收 HTTP

在 todo-web 根目录创建 pom.xml。你已经见过项目的 groupId、artifactId 和 version，这一次主要增加 parent、Web 依赖和运行插件。完整内容如下：

<project xmlns="http://maven.apache.org/POM/4.0.0"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0
                             https://maven.apache.org/xsd/maven-4.0.0.xsd">
    <modelVersion>4.0.0</modelVersion>
    <parent>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-parent</artifactId>
        <version>4.1.2</version>
        <relativePath/>
    </parent>
    <groupId>com.example</groupId>
    <artifactId>todo-web</artifactId>
    <version>0.0.1-SNAPSHOT</version>
    <properties>
        <java.version>21</java.version>
    </properties>
    <dependencies>
        <dependency>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-starter-webmvc</artifactId>
        </dependency>
    </dependencies>
    <build>
        <plugins>
            <plugin>
                <groupId>org.springframework.boot</groupId>
                <artifactId>spring-boot-maven-plugin</artifactId>
            </plugin>
        </plugins>
    </build>
</project>

parent 让项目采用 Spring Boot 4.1.2 管理的依赖版本。这样 Web 组件、JSON 工具和服务器使用兼容的一组版本。relativePath 为空，表示不去上层目录寻找父项目。

spring-boot-starter-webmvc 带来接收 Web 请求常用的组件，包括 Spring MVC、内置服务器和 JSON 转换支持。它不是我们手写的一个类，而是 Maven 根据这项依赖取来的一组工具。此时先只加这一项，校验和测试用到时再添加。

build 中的插件让 Maven 能用 spring-boot:run 启动应用。你只需要知道这几块各负责什么，以后查依赖时就能找到该增加的位置。

让熟悉的 main 启动服务

在 src/main/java/com/example/todo 中创建 TodoApplication.java：

package com.example.todo;
import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;
@SpringBootApplication
public class TodoApplication {
    public static void main(String[] args) {
        SpringApplication.run(TodoApplication.class, args);
    }
}

package 与目录对应。两个 import 引入刚加入的 Spring Boot 工具。main 仍是程序入口，SpringApplication.run 从这里准备应用并启动服务。@SpringBootApplication 标记配置入口，Spring 从这个包向下寻找控制器等组件。

写一句真正由我们处理的回复

在同一个目录创建 HelloController.java：

package com.example.todo;

import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RestController;

@RestController
public class HelloController {
    @GetMapping("/hello")
    public String hello() {
        return "你好，任务清单";
    }
}

hello 方法只是返回文字。@GetMapping("/hello") 把它与 GET /hello 对应起来。@RestController 告诉 Spring 找到这类处理组件，并把方法返回值写进响应。以前 println 把文字发给终端，这里 return 把文字交给框架，再由框架发给浏览器。

告诉它使用哪个端口

在 src/main/resources/application.yaml 写下：

server:
  port: 8090

这两行只设置监听端口。server 是一组服务配置，port 是其中的端口，缩进表示它们属于同一组。暂时没有其他配置。

现在项目中应该有这些文件：

todo-web/
├── pom.xml
└── src/main/
    ├── java/com/example/todo/
    │   ├── TodoApplication.java
    │   └── HelloController.java
    └── resources/application.yaml

在含 pom.xml 的目录运行 mvn spring-boot:run。首次需要等待 Maven 获取依赖。服务启动后，在浏览器打开 http://127.0.0.1:8090/hello，应该看到“你好，任务清单”。如果 8090 被占用，先在 YAML 中换一个端口，访问时也使用相同端口。

这时先顺着代码看一遍：main 启动服务，Spring 找到 HelloController，登记 /hello。浏览器访问时，框架执行 hello，拿到返回文字，写入 HTTP 响应。你已经亲手写完了这一条路。

接下来，把同一条路换成查询任务

有了 /hello，才开始增加任务。先写 TaskService.java，仍放在同一个包里。它暂时保存内存任务，代码如下：

package com.example.todo;
import org.springframework.stereotype.Service;
import java.util.Comparator;
import java.util.List;
import java.util.concurrent.ConcurrentHashMap;
import java.util.concurrent.atomic.AtomicLong;
@Service
public class TaskService {
    public record Task(long id, String content, boolean done) {}
    // 此阶段只观察 Web 请求；程序重启后，内存中的任务会消失。
    private final ConcurrentHashMap<Long, Task> tasks = new ConcurrentHashMap<>();
    private final AtomicLong sequence = new AtomicLong();
    public Task create(String content) {
        Task task = new Task(sequence.incrementAndGet(), content.strip(), false);
        tasks.put(task.id(), task);
        return task;
    }
    public List<Task> list(boolean onlyOpen) {
        return tasks.values().stream().filter(t -> !onlyOpen || !t.done())
                .sorted(Comparator.comparingLong(Task::id)).toList();
    }
    public Task find(long id) {
        Task task = tasks.get(id);
        if (task == null) throw new TaskMissing();
        return task;
    }
    public Task finish(long id) {
        Task result = tasks.computeIfPresent(id, (key, old) -> new Task(key, old.content(), true));
        if (result == null) throw new TaskMissing();
        return result;
    }
    public void delete(long id) {
        if (tasks.remove(id) == null) throw new TaskMissing();
    }
    public static class TaskMissing extends RuntimeException {}
}

record Task 把编号、内容和状态放在一起。sequence 分配编号，tasks 按编号保存任务；ConcurrentHashMap 和 AtomicLong 用来协调多个请求同时操作的情形。@Service 让 Spring 创建并管理这个对象。list 收集符合条件的任务，find 查单条，create 新增，finish 修改状态，delete 删除。TaskMissing 表达查不到任务，下一篇再把它整理成 HTTP 错误。

然后创建 TaskController.java，先只接查询：

package com.example.todo;

import java.util.List;
import org.springframework.web.bind.annotation.*;

@RestController
@RequestMapping("/api/tasks")
public class TaskController {
    private final TaskService service;

    public TaskController(TaskService service) {
        this.service = service;
    }

    @GetMapping
    public List<TaskService.Task> list(
            @RequestParam(defaultValue="false") boolean onlyOpen) {
        return service.list(onlyOpen);
    }

    @GetMapping("/{id}")
    public TaskService.Task find(@PathVariable long id) {
        return service.find(id);
    }
}

类上的 /api/tasks 给这组接口共同前缀。没有子路径的 @GetMapping 查列表；/{id} 把 /api/tasks/3 中的 3 交给 long id；@RequestParam 则读取 ?onlyOpen=true。路径说明操作哪条任务，查询参数补充筛选条件。构造方法把 TaskService 交进来，这段装配会在工程化一篇继续解释。

每次改完先停止旧进程，再运行 mvn spring-boot:run。访问 /api/tasks 会看到 []，因为此时还没有接收新增请求。下一篇就在这个自己写好的工程上接 POST，不需要另外取一份项目。
