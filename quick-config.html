5. 配置与日志

只记住改哪里，不需要重写配置加载代码。

你要改什么启动时写什么
端口PORT=8093 mvn spring-boot:run
访问密钥APP_API_KEY=新密钥 mvn spring-boot:run
网页来源WEB_ORIGIN=http://127.0.0.1:5173 mvn spring-boot:run
上传目录UPLOAD_DIR=/绝对路径/attachments mvn spring-boot:run
每秒请求上限REQUESTS_PER_SECOND=10 mvn spring-boot:run

这些名字在 application.yaml 的 ${变量名:默认值} 中声明。YAML 放默认配置，环境变量传本次环境的值。密码不提交到 Git。Spring Boot 默认不会自动读取任意 .env 文件；本教程直接在启动命令前传值。

记录一条业务日志

// 放在需要记录日志的类中：
private static final org.slf4j.Logger log =
    org.slf4j.LoggerFactory.getLogger(TaskService.class);

// 放在方法里，值由自己的业务变量提供：
log.info("task_created id={}", taskId);
log.warn("task_rejected reason={}", reason);
log.error("task_save_failed", exception);

这里只展示日志片段，不要把尚未声明的 taskId、reason、exception 直接复制进方法。把值换成当前代码里已有的变量。INFO 写关键正常事件，WARN 写需要关注的问题，ERROR 写失败；排查细节用 DEBUG。不要记录密码、密钥或完整私有正文。

调级别、切成结构化输出

# 只在开发排查时，增加 application.yaml 中这一项：
logging:
  level:
    com.example.quick: DEBUG

# 想输出 JSON 日志时，在同一个 logging 下增加：
  structured:
    format:
      console: logstash

上面是同一 logging 配置下的片段，应合并进原配置，不要建立两个 logging 顶层键。结构化输出时不再依赖原来的文本 pattern。requestId 会随日志上下文输出；先用它找到同一次请求。跨多个服务的 traceId 需要接入链路追踪组件及传播配置，不能仅靠复制一个随机字段完成。

固定排查方法：浏览器或 curl 记下 X-Request-ID；在终端日志里找同一个编号；看 status 和 durationMs，再看具体错误。
