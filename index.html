01 / 回顾

先知道自己在哪里

打开终端，就像打开了一个可以用文字操作的文件管理器。你总是在某个目录中；想操作文件，先弄清当前位置。

pwd       # 显示当前目录
ls        # 列出当前目录的内容
ls -l     # 显示更详细的信息
cd code   # 进入 code 目录
cd ~      # 回到用户主目录

ls -l 显示的每一行包括类型、权限、所有者、大小、修改时间和名称。例如，开头的 d 表示目录。你想确认一个文件是否存在，用 ls；需要查看权限或修改时间，用 ls -l。

创建、查看和整理文件

mkdir practice             # 创建目录
cd practice
touch notes.txt            # 创建空文件
echo "第一行" > notes.txt   # 写入内容
echo "第二行" >> notes.txt # 追加内容
cat notes.txt              # 查看内容
mv notes.txt study.txt     # 重命名
cp study.txt backup.txt    # 复制
注意：> 会覆盖原有内容；>> 会在末尾追加。练习时请在自己创建的目录中操作。
02 / 回顾

让命令配合工作

假设主目录里有很多内容，你只想找名称中包含 Doc 的行。可以先列出，再筛选：

ls ~ | grep Doc

| 叫管道：把左边命令的输出交给右边命令。这里 ls ~ 列出主目录内容，grep Doc 筛选包含 Doc 的行。

环境变量：程序可以读取的配置

echo $HOME                 # 查看用户主目录
echo $PATH                 # 查看命令搜索路径
which git                  # 查看找到的 git 位置
export STUDY_TOPIC="command line"
echo $STUDY_TOPIC

PATH 是一组目录。输入命令时，终端会按顺序在这些目录中查找可执行程序。用 export 设置的变量会传给当前终端启动的程序；上面的设置通常只在当前终端会话中生效。

03 / 当前章节

服务启动不了：谁占用了端口？

你准备启动后端服务，让它运行在 8000 端口，却看到 Address already in use。这通常表示已经有程序占用了这个地址和端口。该怎么找到它？

本节做一次实验：

启动服务 → 查找占用 → 关闭服务 → 再次检查

先认识进程和端口

进程是正在运行的程序，每个进程都有编号，叫 PID。端口帮助客户端找到电脑上的服务。例如 http://localhost:8000 中，localhost 指当前电脑，8000 是端口号。

动手实验：制造一次端口占用

打开终端，运行：

python3 -m http.server 8000

这会启动一个简单的 HTTP 服务。看到 Serving HTTP ... port 8000 后，保持它运行，再打开第二个终端窗口或标签页，运行：

lsof -i :8000

你可能会看到类似结果：

COMMAND   PID     USER   ...  NAME
Python  12345  jiyuebo   ...  *:8000 (LISTEN)
看到的内容表示什么
Python使用端口的程序名称
12345进程的 PID；你的数字会不同
LISTEN进程正在监听端口，等待连接
要点：lsof -i :8000 帮你回答“哪个进程在使用这个端口”。如果没有输出，通常表示当前没有可见进程使用该端口。

关闭服务，再查一次

回到第一个终端，按 Control + C，停止刚才在前台启动的服务。然后在第二个终端再次运行：

lsof -i :8000

如果没有输出，就说明刚才看到的端口占用已经消失。实际排查时，先确认进程是什么程序，再决定如何处理。

再看一眼正在运行的进程

ps aux | grep python

ps aux 列出进程，grep python 筛选包含 python 的行。结果中也可能出现筛选命令本身；查具体端口时，lsof 更直接。

练习 / 自己判断

你会怎么处理？

假设输出中显示 Python 24680 ... *:8000 (LISTEN)：

  1. 哪个程序正在监听端口？PID 是多少？
  2. 如果它是你在另一个终端启动的服务，你会怎么停止？

先自己试着回答，再把实际输出带回对话中讨论。
